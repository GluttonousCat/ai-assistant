# 量化策略与回测

> 更新：2026-11-14。策略入口 `skills/quant/`；离线执行 `jobs/backtest_quant.py`；页面 `#quant`。

## 一、系统设计

模块化单体，复用已有趋势规则，不为回测复制一套入场公式：

```text
jobs.backtest_quant → skills/quant/prepare → skills/trend/evaluated_bars
                    → skills/quant/engine + metrics + report
                    → tools/market/backtest_data → storage/repositories/backtest
api/quant_api → skills/quant/service → tools/market/backtest_data → storage
web/src/quant/ → platformApi → /api/v1/quant/*
```

`mtf_reversal_v6`复用60F早期反转与日K入场规则；`jobs.backtest_reversal`在原五指数同池、原结构止损+2R（40日、单笔风险预算0.5%）下做2026固定参数对照，不混入扩池效果、不搜索退出参数。当前名单回放有前视/幸存者偏差，2026设计样本不属于独立样本外。

此前`registry.py`注册`mtf_dual_v5`、`mtf_pullback_v5`、`mtf_rebound_v5`：60F确定趋势、日K确认入场，使用M8/M13/M21简单均线。
`jobs.backtest_mtf`读取两周期原生行情，`prepare_mtf`复用`skills/trend/mtf.py`纯计算，然后在原生日K执行资金回测。
旧`trend_dual_v4`、`trend_pullback_v4`、`base_rebound_v4`三项保留历史定义及结果，仍可由旧任务显式重放。
入场公式、前置证据和推进计数详见[股票行情](../frontend/stock_dashboard.md)。
v4.1增加“初次反转/回调再起”的背景分类，修正首阳观察名称；入场掩码、计数与止损不变，
注册ID继续使用v4，版本字段记录实际代码版本。已有12组v4回测保留原结果；本次分类修复未重算，不能宣称收益改善。

`models.py`保存执行参数；`prepare.py`清洗与纯计算；`engine.py`管理资金/订单/持仓；
`metrics.py`计算净值与成交统计；`report.py`输出JSON、CSV、Markdown与静态净值图。
行情/结果SQL只在仓储层。HTTP只读已完成结果，不采集行情、不启动全池计算、不做DDL。

数据库：`stock.daily_price_limit`保存真实历史涨跌停价；`stock.backtest_run`保存版本、参数、
完整日净值、数据审计和未平仓；`stock.backtest_trade`逐笔保存已平仓结果，按页查询。
每个组合结果与其成交在同一事务发布；同一组实验用`suite_id`关联，各组合分别完成后可读。
DDL由`storage/schema/quant.py`使用独立连接部署。

## 二、需求优化

- 平台新增“量化策略”：策略库、回测对比、策略与两条基准净值、成交分页、未平仓与执行审计。
- 2026数据运行两周期×三策略×两名单口径，共12个独立资金组合，避免把单股信号胜率误当成组合收益。
- 固定名单全年研究和实际已知名单之后的回放分开标记；不把有偏股票池的高收益称作无偏业绩。
- 结果记录收益、最大回撤、费用、仓位、已平仓胜率/盈利因子；不强制平掉期末持仓来美化结果。
- 首轮退出参数预先固定，不根据本次收益调参。策略已参考过2026图例，本次属于样本内检验。
- v5.1按最后补充改为60F趋势、日K入场；有限比较三种退出，开发段选出方案后固定检查后续时段，保留全部结果。

| 问题 | 根因 | 处理方案 |
|---|---|---|
| 同一收盘既判断又成交会引入前视 | 入场筛选公式只定义信号，没有执行时序 | 前根收盘信号，下一根开盘尝试成交；缺失下一根时不在复牌后追买旧信号 |

| 基准写入失败 | 供应商返回pre_close/change，旧index_daily表没有这些字段 | 只保存表中定义的列，修复后重试；涨跌停按已完成日期断点续传 |
| 复权后盈利与实际份额/费用混用 | 除权价差不能当亏损，且仅因子无法拆分现金红利与送配 | 首因子归一计算信号，用因子份额调整近似经济价值；明确不是逐笔权益会计 |
| 同根既触及止损又触及止盈时选有利路径 | OHLC无法恢复先后顺序 | 已知开盘触发先处理；其余同根双触发按止损先处理 |
| 旧60F双机会1259笔中1110笔短均线退出 | EMA5退出对短周期噪声敏感，入场与退出假设未分别验证 | 60F只做背景，改在日K确认入场；同入场有限比较单根均线、结构止损与盈利跟踪；不能将所有亏损都归因于退出 |

| 旧收益/胜率失真，不能作为优化基线 | `to_numpy`返回视图后，指标复权原地修改了执行用原始价，买入可能再次乘因子 | 原始数组copy与复权数组隔离，执行前校验raw×scale=adjusted；新执行版本raw-adjusted-separated-v2；标记旧批次失效，重算新方案及同输入旧日K基线 |
| 盈利保护对照在未触线的开盘提前退出 | 链式条件表达式把“止损已上移”误当成触价条件 | v3明确先检查开盘是否触线；补充全根在保护线上方不得卖出的反例，重跑全部对照，保留并标记v2对照批次失效 |

## 四、处理方案

### 2026-11-14 对应的分段离场（实验策略）

`exit_policy=reversal`只允许原生日K撮合，独立`skills/quant/reversal_exit.py`决策；M8/13/21入场保持对应框架，退出用日K结构，未冒充盘中60F卖出择时。
1. 原始结构止损始终保留；买入当日触发遵守T+1，跌停/停牌不能保证按止损价成交。
2. 持有5个交易日仍未推进0.5R、收于成本下方，排队下一交易日开盘退出。
3. 日收盘盈利达到1R，止损加入成本/估算卖出费用和滑点缓冲；峰值达到2R后，按峰值减2.5ATR跟踪，不固定2R全部卖出。止损只升不降，下一根生效；跳空仍可能亏损。
4. 峰值至少推进1R，且必须先收复日K M21，之后连续2个收盘失守、且至少持有4日才触发趋势退出；从未收复不叫失守。40日超时退出兜底。
`jobs.backtest_reversal_exits --offline`复用项目生成的v6.1缓存及冻结报告交易日历、真实限价，不访问PG；`--publish-only`按已有run_id幂等发布完整full报告。正常模式按工作单元重连重试，保留两方案，不按窗口成绩选胜者。前端默认仍选结构止损+2R，分段离场可查看实验对照。



### 4.0 当前v5.1的入场、退出与对照设计

入场条件见[股票行情v5.1](../frontend/stock_dashboard.md)：当天完整60F确认趋势或止跌修复，
原生日K有回调/阴跌背景及合格转强阳线，收盘确认后下一交易日开盘尝试买入。
信号使用上一根ATR衡量实体/初始风险；真实复权因子缺失、分钟缺根、真实限价缺失均不补造交易。
同股冷却5个交易日；组合已有该股时不重复加仓，因而“图上规则通过”不保证组合有空位执行。

在看本轮收益前声明三组有限方案，保留相同入场、费用、滑点、T+1、真实限价与仓位条件：

| 退出方案 | 硬止损 | 盈利退出 | 均线退出 | 最长持有 |
|---|---|---|---|---|
| single_line_2r（对照） | 固定初始结构止损 | 2R | 单根收盘失守M21 | 20根日K |
| structure_2r | 固定初始结构止损 | 2R | 不因单根均线失守退出 | 40根日K |
| protected_3r（对照） | 保留初始硬止损，保护只上移 | 1.2R后成本缓冲/2.5ATR跟踪，3R目标 | 至少持有4根后连续2根失守M21 | 60根日K |

R固定为实际模型开盘买入价至初始止损的距离；次日大幅跳空使风险>5%时拒单，不按昨日收盘假设成交。
初始止损至少1.25个日K ATR，并守住近3根日K结构低点外侧。每股目标仓位最多10%，最多10只，
单笔初始风险预算最多净值0.5%；预算不能保证跳空/跌停后仍只亏此金额。
跟踪保护仅由已收盘K线更新、下一根生效，不拿本根最高价更新后倒卖在本根较早低点。
保护缓冲按佣金/滑点/税费比例近似，最低佣金与成交缺口仍可能使实际保护退出亏损。
未平仓不强卖；长等待可能占用仓位，不能用个例单股回放替代组合收益。

开发段为2026-01-01—06-30；至少30笔平仓才可参与选择，以净收益/最大回撤（分母下限1%）比较。
选定后固定评估07-01—08-31、09-01—11-12和全年；分段从空仓开始，分段收益不能直接拼接成年收益。
8月24日及11月个例在设计前已知，固定名单也非历史成分，因此时间留出仍不是严格未见样本，更不是实盘验证。
若全年仍负收益或盈利因子<1，必须如实呈现；不以提高胜率为由隐藏亏损交易或较差方案。

`jobs.backtest_mtf --prepare-only`仅准备本地缓存；`--resume`检查冻结参数再执行，
输出`declaration.json`、`selection.json`、所有分段/方案JSON与成交/净值CSV、`comparison.json/csv`、
`README.md`与独立净值图`exit_comparison.png`。完整结果写PG；旧任务不把v4行情误用于v5策略ID。
存在数值缺陷的历史批次可由仓储层标记`diagnostics.superseded`及原因，保留其指标，页面明确提示并跳过默认选择。
回测原始价与复权价必须为不同内存；撮合前逐股校验OHLC的raw×scale=adjusted，失败即拒绝运行。
原始价隔离修复版本为`raw-adjusted-separated-v2`，当前`price-units-and-protected-stop-v3`追加保护线触价校验；不能用修复前的失真负收益宣称策略改进。
已知旧派生缓存仅在拥有复权OHLC与已知scale时可逆恢复原始单位，参数/计算版本须匹配；
重算会创建新suite并记录来源，而非覆盖旧指标。恢复后另对真实供应商原始价抽查。
`--legacy-daily`从同一原生行情缓存重算旧v4日K策略，用相同正确执行单位建立可比基线。

### 4.1 固定执行假设

以下为旧v4原始对照的执行默认值（v5.1显式使用上面的退出方案）：
100万元现金，最多10只，单只目标10%，不融资、不做空。候选按信号当时质量与代码排序；
被仓位拒绝的信号可在后续仍满足第2—4阳条件时重试，已买过的同股票/类型/启动段不重复买。
主板/创业板/BJ入场按100股整手处理，科创板至少200股；BJ和科创板采用100股步长是保守简化。
开盘仓位只用当时现金与开盘估值，日内退出资金不能用于同根更早的开盘买单。
买入规模还限于前一根已知成交量的1%，不使用未来本根成交量决定买入数量。

佣金双边0.03%、最低5元，过户费双边0.001%、印花税卖方0.05%，滑点单边5bp，均随结果冻结。
佣金是研究假设，不代表任何券商实际报价。成交价是滑点后的理论模型价，无逐笔盘口或排队成交承诺。

退出：信号结构止损固定；以实际模型买入价至止损距离定义R，2R止盈；A失守EMA20、B失守EMA5，
或持有20根K线后，排入下一根开盘卖单。20根对60F约5交易日，对日K约20交易日。
买入跳空后风险超过8%或止损已在买入价上方时拒买。T+1、限价和缺失行情可能使实际模型退出晚于触发。
日内条件单的时间按所在K线结束时刻记录，开盘触发则记录开盘时刻；不伪装成逐笔成交时间。

### 4.2 复权与数据口径

只读原生不复权价格与当天真实因子；按`raw × 当天因子 / 首个已知因子`计算指标，归一基准不依赖未来。
入场手数使用实际原始价；持仓经济份额按因子比例调整，近似复权总回报，含现金分红再投资的近似，
不还原现金到账日、送配股、配股缴款或分红税。不能将此模型结果当作券商资金流水。
缺失行情不伪造K线；停牌持仓沿用末次已知估值，并展示末次报价时间。结束时保留未平仓。

最大回撤与Sharpe为每日收盘资金净值口径，Sharpe无风险利率假设0，年化按252交易日。
胜率、盈利因子、平均单笔收益只统计已平仓且已扣费用的交易，未平仓计入组合总收益。
中证1000/沪深300为价格指数，未含指数分红，与个股复权收益并非完全一致的总回报口径；缺少基准日期不填值。

### 4.3 名单与可解释边界

`fixed_snapshot`：使用结束日可取得的最近五指数成分并集回放全年，明确存在成分前视和幸存者偏差。
`observed_only`：信号时间不得早于该股票成分名单的实际`fetched_at`（上海时间），此前行情只作指标预热。
当前已知名单入库晚于11月12日收盘，所以严格口径没有交易样本，不能据此评价策略优劣。
历史ST/退市状态未恢复，只能按当前简称过滤；年初没有2025预热数据，首批信号晚于数据起点。
本次不搜索最优参数，不承诺未来收益；仍需以后新增样本和真正的历史成分/公司行为台账检验。
