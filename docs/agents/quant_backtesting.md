# 量化策略与回测

> 更新：2026-11-18。策略入口 `skills/quant/`；离线执行 `jobs/backtest_quant.py`；页面 `#quant`。

## 一、系统设计

页面已升级为策略创作工作台（workspace v2，保留v1模板）：在表单制定60F底背离反转/上涨回调规则，或通过自然语言生成可编辑的参数草稿；预览后保存不可变版本、提交后台回测，再查看净值及逐笔/分批成交。组合模式通过声明式条件树自由组合60F/日K指标、比较、交叉、全部/任一条件及嵌套分组；模板模式保留原v8形态与442/532。日K指标只有用户明确添加时才参与条件；所有订单仍在次日开盘执行，不生成任意Python代码。

分层：`api.quant_api → skills.quant.workspace/workspace_models → tools.market.quant_workspace → storage.repositories.quant_workspace`；应用启停由`jobs.lifecycle`启动`jobs.quant_worker`，后者以OS锁串行监督独立进程，调用`workspace_runner → prepare_swing或rule_prepare → engine/tranche_engine`。单任务默认15分钟超时，配置`quant.workspace_timeout_seconds`（10—3600秒）；超时或关闭服务会终止该任务进程树并释放队列。HTTP只保存配置、入队及读取状态/报告，不抓供应商行情、不在请求中运行回测。

工作台按JWT用户隔离，策略版本、任务及结果原子保存于`output/quant/workspace/{drafts,tasks,results}`。每次保存产生新版本，每次任务冻结配置和区间；修改或复制不会改旧成绩。队列请求编号幂等，同编号不同参数拒绝；单用户最多3个未完成任务、全局最多20个。启动遇到上次running任务，已有完整结果则恢复完成，否则标为中断，不悄悄重复运行。此版本是单机文件持久化，迁移部署需要同时备份output目录；不是分布式任务系统。

自然语言使用统一LLM工厂与独立system prompt，只允许解析到严格校验的配置。解释、默认假设与未支持条件随草稿保存；未支持要求即使保存/重新加载后也不能提交。页面要求检查生成规则；若改用表单，需明确移除未实现的要求。禁止任意执行模型代码。`max_holding_bars`在工作台以交易日计，`cooldown_bars`才是60F根数。

`online_priority.py`（v21）把已结束的历史辅助结果用于每月一次的指数相对强弱排序：特征、标签、训练截止、模型标准化及候选应用集中于纯领域模块；`jobs.research_online_60f`仅编排本地输入、冻结声明、资金回放与报告发布。仍复用v8 balanced的60F底背离/上涨回调，不新增日K形态，不把预测分数当作保证收益。正式实现与原型的信号、净值、逐笔和费用对照一致。正常成本全区间历史门槛已通过，实验仍不自动变为默认。

`candidate_quality.py`按股票代码及触发身份从原始冻结信号恢复质量分，保留独立的模型排序分与成交证据。v8原始质量分范围为0—120，与前端既有v7评分定义不同；72分门槛不能套到月度模型约0—3的预测值上。`stop_orders.py`提供可选的预挂保护单研究：严格校验原生60F与日K原价，基础方案只用上日已确定止损；跳空按原生开盘价、逐批T+1和分时成交量约束。数据不一致的日期只有研究脚本明确选择时才使用标注为`1D_fallback`的日K条件单近似，不修写分钟价格。默认仍为盘后判断、次日执行。

`support_protection.py`独立计算已确认的60F更高低点及形成/确认时间，只允许买入后形成、已被右侧两根K线确认的支撑在盘后上移保护位。`IntradayProtection`是另一种显式执行假设：在完成60F的收盘浮盈达到双门槛后，将保护价提高到含费用/滑点的成本线，仅从下一根K线生效；不拿当前K线较早的低点回填新止损。两种研究均复用分批账户及固定风险预算，不在默认工作台自动启用，也不提交券商订单。

`label_research.py`编排辅助标签比较与绝对收益确认。只从旧缓存按代码/时间/原价/因子基准匹配恢复两列已验证的因果波动特征，绝不借用缓存的预测值替代原始质量分；所有原始候选参与新模型训练，未结束的当前标签仍允许获得预测。绝对收益模型与指数相对模型各自按月只学已结束标签；成交证据同时记录两种预测与原始质量，实验报告保存实际模型配置，防止把新模型结果标成旧参数。

`skills/trend/wyckoff.py`提供独立的量价事件状态机，`skills/quant/wyckoff.py`把已完成60F事件映射为盘后计划；没有价格均线站位或MACD条件。`tranche_engine`的显式`wyckoff_policy`复用原账户、分批、风险和T+1，只改变量价进攻/防守语义。独立策略`wyckoff_60f_v31`限研究，暂不进入可执行工作台目录；旧单次引擎拒绝此策略，旧批量任务跳过它，避免把旧信号误标为量价策略。

`skills/quant/wyckoff_hybrid.py`在量价入场的基础上只给LPS趋势回调增加均线门槛。底部反转沿用Spring低量测试及需求确认。两类持仓都按量价支撑及供应变化管理。

`market_context.py`集中计算沪深300/中证1000的原生60F状态、滞后一根的历史beta与个股相对表现；只提供研究用环境证据，不生成个股买点。`signal_priority.py`隔离相对强弱与结构距离排序，`tranche_prepare.confirm_signal_close`只比较原60F触发价到当日最后60F的保持情况。`jobs.research_market_context`统一编排指数、分批节奏、排序和软退出耐心四轮研究，避免为每轮复制撮合器；HTTP不抓指数或运行研究。所有新方案仍限实验，不自动替换默认。

`v10`分批资金模型独立于旧撮合器：`tranches.py`保存442/532计划及按批次T+1/FIFO成本，`tranche_engine.py`按完整持仓周期回测，`tranche_prepare.py`只接完成60F确认；`jobs.research_tranches`复用冻结v8/v9入场做固定对照。部分已实现收益与剩余浮盈分别入账，分批卖出不重复计胜率；旧引擎和历史成绩不修改。

`v9`有序结构研究：`skills/trend/structure.py`用时间状态记录推进、回调、缩量及恢复；`skills/quant/structure_exit.py`只用入场后形成的已确认60F低点保护持有。`jobs.research_ordered_60f`固定7组入场/退出/执行方式对照，不搜索参数或按全年收益挑选赢家。旧v8/v8.1规则与产物不改写，HTTP仍只读完整报告。

新增独立的`v8`主板研究：`skills/trend/swing.py`只在60F上计算M8/13/21、MACD底背离与上涨回调；`prepare_swing`把当日完整60F机会汇总为盘后计划，日K仅提供原生撮合价格、流动性与估值，不再要求日K阳线形态。`jobs.cache_mainboard_minutes`显式离线缓存同一新浪源，`jobs.research_mainboard_60f`固定参数表、开发段选择、后续分段检验。旧v4—v7公式与报告保留冻结定义。

## 二、需求优化

v2创作模式支持：开高低收、名义收盘价、MA/EMA、Wilder RSI、ATR、固定12/26/9 MACD（柱=DIF−DEA）、前N根均量的量比、前N根最高/最低及N根涨幅；周期为60F或日K，指标可带非负历史引用及正倍数。条件支持大于/大于等于/小于/小于等于/上穿/下穿，分组支持全部/任一并可嵌套。入场与离场各自定义；可选15:00采样或当天任一完成60F、条件由假转真或持续满足、冷却根数。组合模式首版单次进出；自定义442/532暂未实现，明确拒绝，原模板分批继续可用。


工作台支持选择主板/五指数并集/单指数、反转或回调方向、入场实体/量比/背离/回调深度、风险距离、流动性、资金/仓位、费用滑点、三种单笔退出，以及单次/442/532独立买卖计划。分批时使用既有分批引擎，不会将单笔R目标、ATR保护参数误显示为生效规则；增仓0.5R/1R及完成60F确认、尾仓结构退出沿用原模型。用户可快速检查前50/200只或运行全池；按代码截取的快速样本不能代表全池效果。

日期可用性取60F、日K、复权和真实涨跌停的共同末端；运行前再校验交易日及逐股限价。开始日前最多180个自然日用于指标预热，仍不早于2026-01-01，预热行情不计入组合收益。当前股票池依赖已取得的成分名单，仍有成分/幸存者及历史ST偏差。

- 2026-11-16：回测成交和未平仓使用共享机会标签：蓝色↑趋势回调、紫色■底部反转，缺失分类显示待识别；与股票行情列表及K线图例一致。显示层命名统一不改写持仓family、成交或历史收益，详见[股票行情标注](../frontend/stock_dashboard.md)。
- 平台新增“量化策略”：策略库、回测对比、策略与两条基准净值、成交分页、未平仓与执行审计。
- 2026数据运行两周期×三策略×两名单口径，共12个独立资金组合，避免把单股信号胜率误当成组合收益。
- 固定名单全年研究和实际已知名单之后的回放分开标记；不把有偏股票池的高收益称作无偏业绩。
- 结果记录收益、最大回撤、费用、仓位、已平仓胜率/盈利因子；不强制平掉期末持仓来美化结果。
- 首轮退出参数预先固定，不根据本次收益调参。策略已参考过2026图例，本次属于样本内检验。
- v5.1按最后补充改为60F趋势、日K入场；有限比较三种退出，开发段选出方案后固定检查后续时段，保留全部结果。

## 三、问题

| 历史问题 | 根因 | 处理方案 |
|---|---|---|
| Spring测试后右侧跌出更低点仍可能沿用旧测试低点 | 只核对Spring大底未破，没有重新核对测试自身的右侧确认 | v33在右侧出现更低点时清空该测试并重新等待；新测试需重新经过两根完整K线，不把支撑标到较早的高低点 |
| 盘中已确认需求到15:00未再次触发时漏进攻 | 原加仓状态只读取15:00那一根的瞬时事件 | v33按同日已完成事件保持到收盘的状态发布；原生收盘未退回超过0.25ATR且中途未破防守、无供应警报时才保留，不增加日K形态门槛 |
| 原进攻和部分离场仍依赖均线站位 | 原scale_in_ready和tranche_trend_failed来自M8/13/21 | 独立量价版用Spring测试/LPS/SOS与供应警报，原均线和模型只作清楚标识的对照；不把旧公式改名成威科夫 |
| 只看到大成交量就认作派发 | 未区分位置、价格推进和后续供给确认 | 警报须在此前较大波动的高位区域，且量大、收盘偏弱、推进不足；先停加仓，后续弱势确认才减一批；低位放量不直接认定派发 |
| 防守减仓后止盈累计目标可能错位 | 若从剩余仓位重建卖出基数，会与已售数量混淆 | 第一次减仓锁定当时持仓基数，按原532/442累计权重处理，减仓后禁止加仓；成交完成后才推进退出阶段 |
| 初次基准对账比较了不同净值结构 | 新回放净值尚未附基准曲线，旧冻结报告已有benchmarks字段 | 在对账前按日期附同源基准；v31预检失败记录保留，不计有效实验；v32参数不变，缓存需同时验证原输入/量价准备源码/参数哈希后才可复用 |
| 辅助标签与组合规则不完全一致 | 原标签允许4%买价风险/10交易日，实际组合2.5%/20日/532 | v29预先冻结7组风险、持有、止盈或预热变体，原执行和风险预算不改；标签仍为单买单卖近似，不假称已复制完整分批结果 |
| 相对强势不代表绝对盈利 | 指数相对收益为正的预测可对应市场下跌中的亏损 | v30独立训练绝对收益头，固定4组确认/组合排序，按相同开发段标准筛选；实际失败结果留存，不把额外模型当作盈利保证 |
| 名义532实际大多只有首批 | 加仓需价格创新高且实际入场风险仍≤2.5%，原止损未上移时加仓可能被拒绝 | 独立研究买入后已确认支撑上移，保留逐笔保护价/账户风险预算证据；不能为了买满而提高风险距离 |
| 提高保护价后回填同一根K线的低点会产生虚假成交 | 一根OHLC不含内部顺序，当前低点可能早于确认上涨的收盘 | 盘中保护在完成60F收盘后更新，下一根开始才可触发；首日触发仍按T+1延迟，次日反弹不取消已激活卖单 |
| 72分门槛可能误筛月度排序缓存 | 旧缓存用score覆盖原始质量，预测值与质量分量纲不同 | 按代码和触发身份恢复quality_score，独立priority_score，核对时间轴、类型和止损尺度，成交证据保留两分数；不改旧缓存 |
| 复制分批报告参数时无法重放 | 报告把外层exit_policy=tranches覆盖到基础配置，基础配置不接收此枚举 | 从冻结报告恢复外层计划时显式恢复基础legacy策略，撮合结果逐项对账 |
| 把收盘止损误认为实际损失上限 | 收盘确认后次日卖出，隔夜跳空或跌停可显著扩大损失 | 明确区分计划距离和实现亏损；独立比较预挂保护单，不伪造按止损价成交，不自动改默认 |
| 新浪60F汇总与既有日K小幅不一致 | 部分日期高低点或收盘价相差超过一分钱，不能视作逐分钟准确 | 严格模式拒绝；研究可显式采用当日日K OHLC近似，保留日期与成交分辨率审计，禁止按未来全年质量剔除股票 |
| 原页面只能读后台报告，不能制定和运行策略 | HTTP与研究脚本分离但缺应用工作流 | 增加配置/草稿/任务/结果四个步骤，复用现有引擎 |
| 自然语言把20交易日换算成80根60F | 持有期字段名包含bars，模型混淆信号与执行周期 | schema和system prompt明确日级单位，真实生成回归 |
| 未支持要求保存再加载后可能丢失 | 仅前端临时展示不足以约束执行 | 未解决要求随版本持久化，入队与执行双重拒绝 |
| 网络中断可能让回测一直占队列 | 同进程线程等待PG，无法可靠中止同步IO | 独立任务进程、超时/关闭时终止进程树；批量行情和成分名单流式读取 |

## 四、处理方案

### 2026-11-18 72分、退出与指数门槛研究

量价方向新增固定研究主方案。方法参考[Wyckoff Analytics编写的教程](https://chartschool.stockcharts.com/table-of-contents/market-analysis/wyckoff-analysis-articles/the-wyckoff-method-a-tutorial)中低量测试供应、SOS后的LPS及努力/结果关系；以下阈值是本项目的量化近似，不是原理论的完整阶段识别，也未实现点数图目标或验证机构真实意图。

- 底部方向：跌破此前20根低点后收回，先有足够区间跨度，再等待更低成交量、更小价差的较高测试低点；测试后至少两根完成K线并恢复需求，才释放Spring-test事件，不回填到历史低点。
- 趋势回调：先有突破前8根高点的有效SOS和至少3%/2ATR推进，再出现受控回撤；仅统计下跌回踩段的量能/价差，缩量比≤0.8、价差缩小且需求恢复时确认LPS。恢复上涨那根的放量不混入回调均量。
- 量能使用过去20个同一时段的平均量，至少5个历史同槽观测；当前量不进入自身基准。ATR只衡量价差/缓冲，不判定价格站上均线。复权价格与逆因子份额量匹配，机械拆股不直接变成需求爆发，但现金权益仍是近似。
- 警报须有高位区间语境、量比≥1.8、收盘偏弱且推进不足；只暂停进攻。其后4根内出现进一步弱势才分批防守；持仓后新形成且已确认的测试支撑，在达到0.5R后允许上移，防守位不降低。跌破支撑或原风险位退出剩余仓位。
- 仍按完成60F制定盘后计划，次日合法开盘执行，日K只用于成交、流动性和估值；没有额外日K阳线或均线要求。信号保留类型、量比、缩量比、收盘位置及支撑形成/确认时间。

`python -m jobs.research_wyckoff_60f`支持`--declare-only`/`--resume`，当前v33首次需准备全池；`--prepared-from`只有在准备源码、参数和所有行情哈希一致时才允许复用其他研究目录的冻结缓存，v33不能直接复用v31旧量价状态。最初v32修复基准曲线对账格式时曾复用v31缓存，量价公式未变化，旧记录保留；当前v33修正测试重新确认及同日需求保持，产物`output/quant/wyckoff_price_volume_v33`。固定三组：原v21对照、原入场+量价管理、纯量价主方案，每组均运行全部预声明窗口与两种成本，不搜索参数或按全年赢家改选。纯量价方案不用旧月度相对排序或指数均线门槛；原入场对照明确保留旧均线影响，不能称为纯量价。仍为532、2.5%实际风险、0.35%账户预算、单股10%、72原始质量门槛。纯量价质量0—100是新定义，不能与旧v8的0—120或前端v7分数当作同一校准概率。

追加v29辅助标签比较与v30双收益头确认。`python -m jobs.research_label_alignment_60f`（支持`--declare-only`/`--resume`）固定7个变体与原模型：标签风险2.5%或4%、10或20交易日、5%或8%目标的指定组合，以及一组250个已结束标签预热对照；岭回归100及19个因果特征不变。原始9789个候选保留，不只重训原模型选出的615个候选。`python -m jobs.research_dual_forecast_60f`（支持`--declare-only`）固定绝对预测≥0/0.25/0.5%三组门槛，以及绝对/相对预测等权排序且绝对预测≥0的一组。两个收益头的分数与原始质量分分离，不用辅助标签是否最终可得过滤当下预测。

两轮仍保持2.5%实际成交风险、账户0.35%、单股10%、532、次日开盘、T+1及费用/涨跌停约束。成本压力复用已拟合模型、完整重放资金路径；模型配置逐报告写入，不能把压力结果回馈当期训练。只允许按1—6月开发段选择，后续已看过的月份不再用于改选。产物位于`output/quant/quality72_labels_v29`及`quality72_dual_forecast_v30`；代码变化会触发原声明拒绝覆盖，冻结源码保留，升级实验需新版本。

复用冻结2333只主板、2026-01-01—11-12、月度因果排序及532资金模型，不增加单股10%上限或账户0.35%风险预算。前端当前筛选与盘中观察显示≥72；历史名单和既有邮件口径保持各自契约。研究中的72仅作用于v8原始质量，所有615个模型候选均通过，不能将此过滤描述成收益提升。

### 2026-11-17 可组合规则与紧凑界面（v2）

价格类比较与交叉使用ATR×1e-8及机器精度下限容差，防止换复权基准后贴合均线的1ULP变为假交叉；非价格指标使用机器精度容差。组合策略v1.1显式记录此次修正。

`rule_models.py`定义有界条件树（总计≤40节点、≤3层）；`rule_indicators.py`只计算前缀可见指标及时间对齐；`rule_prepare.py`编译为既有撮合器所需的日级信号及离场数组。未知指标、负历史引用、缺周期及不复权价/复权指标混比直接拒绝；没有eval、任意代码、SQL或模型生成交易操作。日K按完成时间映射到60F，未完成的当日日K不可提前看到；日K交叉只在完成时产生事件，不向下一天复制。前N根高低点明确排除当前K线。

`RuleExecutionConfig`为独立执行参数，固定止损/止盈从实际买价设置；不启用模板MA软退出、ATR保护、R目标及模板形态。止盈可空，仅按显式离场/止损/最长持有处理。所有阈值均盘后检查、次日开盘执行，受费用、T+1、限价、现金及流动性约束，百分比不是最大实际亏损保证。旧BacktestConfig参数与模板路径不改写。

默认进入“自由组合规则”，保留“已有60F形态模板”切换；自然语言生成同一条件树，可逐行编辑、添加AND/OR组、单独定义离场，再看中文规则预览与冻结JSON。页头标题/导航合为一行，去掉原开场大横幅，压缩提示、间距和输入框；桌面首屏即可看到条件编辑及主要风控字段。移动端条件按操作数分行，不横向溢出。

### 2026-11-15 指数相对强弱、每月因果训练与532（v21）

### 4.1 固定执行假设

以下为旧v4原始对照的执行默认值（v5.1显式使用上面的退出方案）：
100万元现金，最多10只，单只目标10%，不融资、不做空。候选按信号当时质量与代码排序；
被仓位拒绝的信号可在后续仍满足第2—4阳条件时重试，已买过的同股票/类型/启动段不重复买。
主板/创业板/BJ入场按100股整手处理，科创板至少200股；BJ和科创板采用100股步长是保守简化。
开盘仓位只用当时现金与开盘估值，日内退出资金不能用于同根更早的开盘买单。
买入规模还限于前一根已知成交量的1%，不使用未来本根成交量决定买入数量。

佣金双边0.03%、最低5元，过户费双边0.001%、印花税卖方0.05%，滑点单边5bp，均随结果冻结。
佣金是研究假设，不代表任何券商实际报价。成交价是滑点后的理论模型价，无逐笔盘口或排队成交承诺。

退出：信号结构止损固定；以实际模型买入价至止损距离定义R，2R止盈；A失守EMA20、B失守EMA5，
或持有20根K线后，排入下一根开盘卖单。20根对60F约5交易日，对日K约20交易日。
买入跳空后风险超过8%或止损已在买入价上方时拒买。T+1、限价和缺失行情可能使实际模型退出晚于触发。
日内条件单的时间按所在K线结束时刻记录，开盘触发则记录开盘时刻；不伪装成逐笔成交时间。

### 4.2 复权与数据口径

只读原生不复权价格与当天真实因子；按`raw × 当天因子 / 首个已知因子`计算指标，归一基准不依赖未来。
入场手数使用实际原始价；持仓经济份额按因子比例调整，近似复权总回报，含现金分红再投资的近似，
不还原现金到账日、送配股、配股缴款或分红税。不能将此模型结果当作券商资金流水。
缺失行情不伪造K线；停牌持仓沿用末次已知估值，并展示末次报价时间。结束时保留未平仓。

最大回撤与Sharpe为每日收盘资金净值口径，Sharpe无风险利率假设0，年化按252交易日。
胜率、盈利因子、平均单笔收益只统计已平仓且已扣费用的交易，未平仓计入组合总收益。
中证1000/沪深300为价格指数，未含指数分红，与个股复权收益并非完全一致的总回报口径；缺少基准日期不填值。

### 4.3 名单与可解释边界

`fixed_snapshot`：使用结束日可取得的最近五指数成分并集回放全年，明确存在成分前视和幸存者偏差。
`observed_only`：信号时间不得早于该股票成分名单的实际`fetched_at`（上海时间），此前行情只作指标预热。
当前已知名单入库晚于11月12日收盘，所以严格口径没有交易样本，不能据此评价策略优劣。
历史ST/退市状态未恢复，只能按当前简称过滤；年初没有2025预热数据，首批信号晚于数据起点。
本次不搜索最优参数，不承诺未来收益；仍需以后新增样本和真正的历史成分/公司行为台账检验。
