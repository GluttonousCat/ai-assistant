> 目的: **优质研究报告**。方法论源: docs/research/company_industry_guide.md (先通读)。
> 我们不是在写"资料汇总器", 而是构建"证据可回溯、三层分离、假设可验证"的研究系统。

## 一、生产线与三 Agent

```
Stage 1 数据与证据 Agent (事实层)          [T02 Tushare/画像] [T03 年报] [T04 研报]
    → output/research/<ts_code>/ 分片 json (EvidenceShard)
Stage 2 内容生成 Agent (解释层+判断层)      [T05 十章模板] [T06 生成器+引用校验]
    → draft.json (chapters[] 内联 [E:eid]/[V:vid] 引用, hypotheses[])
Stage 3 页面美化 Agent (呈现层)             [T07 图表] [T08 渲染+总装CLI]
    → figs/*.png + report_<日期>.md
横切: [T01 契约与校验] [T09 质量评分卡与端到端验收]
```

## 二、铁律 (从方法论指南提炼, 每个任务都要遵守)

1. **三层分离**: fact(数据可回溯)/view(研报观点, 必标机构+日期)/judgment(假设, 必带验证指标)。
   研报观点**永远**不能当事实句引用; 无证据的数字必须写"待验证"。
2. **证据显式关联**: 一切结论靠 eid/vid 显式引用, 不靠"模型记得"。
3. **回溯**: Fact.source 必须精确到 表.字段 / 年报章节+小节 / report_id。
4. **中文**: 所有面向用户的产出与 LLM prompt 一律简体中文。

## 七、协作规则

1. 每任务开独立分支: `git checkout -b research/T0X`; 不 merge, 完成后回主会话由总设计合并验收。
2. 提交信息格式: `feat(research/T0X): 一句话 (YYYY-MM-DD)`。
3. 代码规范遵 AGENTS.md: `get_logger(__name__)` 禁 print (CLI 最终输出除外); LLM 一律
   `harness/llm.py` 工厂 (get_agent_llm/get_extract_llm), 禁传 enable_thinking;
   JSON 输出 prompt 花括号转义 {{}}; 解析剥 ```json 围栏。
4. 每个任务自带 pytest (放 skills/research/tests/, 不连 LLM/DB 的用例必须可离线跑)。
5. 拿不准就缩小范围交付, 不要越界改别人的文件。
