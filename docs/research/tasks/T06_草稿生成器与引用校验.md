# T06 · 草稿生成器与引用校验 (Stage 2 核心)

> 先读 T00。你独占: skills/research/compose/generator.py, compose/citation_check.py (+ compose/__init__.py)
> 依赖: T01 (load_pack/校验) T05 (模板)。它们在其他分支时, 以 T00 契约与 T05 文档为准写代码,
> 合并时自然接通 (可先自建最小 stub 便于本地跑通, 合并时删除 stub)。

## 目标
`generate_draft(stock, years=5, research_dir) -> Draft`: 逐章生成十章草稿 + 假设清单 + 引用校验 flags。

## 实现要点
1. 载入: `load_pack(research_dir)` 取 facts/views; 按 T05 CHAPTERS 逐章:
   - 按 ch["wants"] 过滤证据子集 (类别: profile/mainbiz/annual/reports), 摘要化
     (每条一行, 控制在 80 条内; 超 30k 字符截断并记 flag)。
   - LLM 调用 `get_agent_llm().invoke(prompt)` — 长文生成, 非流式;
     失败章重试 1 次, 仍败则跳过并记 flag。
2. **引用校验器** (citation_check.py, 纯逻辑可离线测):
   - 数字句启发: 正则找含数字的句子, 无 [E:]/[V:] 标注 → flag "unverified-number: <句摘要>"。
   - 引用存在性: 提取所有 [E:eid]/[V:vid], 对证据集核对, 幽灵引用 → flag。
   - view 句规范: 含 [V: 的句子宜有机构名或"认为"字样 (宽松提示, 不强制)。
   - 结果写 Draft.flags (供 T09 评分与 T08 渲染警告区)。
3. hypotheses: 第 8 章 (未来增长与情景分析, 即模板 HYPOTHESES_CHAPTER_NO) prompt 中要求额外输出 JSON 假设数组, 宽容解析后回填
   Draft.hypotheses (statement/indicators/related_eids)。
4. 写 draft.json (save_draft)。CLI: `python -m skills.research.compose.generator 贵州茅台`

## 验收
茅台: draft.json 十章齐全 (或 flags 说明跳过原因), 每章 used_eids 非空, flags 机制工作;
pytest: 校验器对构造样例 (有引用/无引用数字句/幽灵引用) 行为正确 (离线)。

## 禁止
绕过校验器直接产稿; 改 T05 模板内容 (结构问题记入提交说明, 由合并者分发); 流式输出。
