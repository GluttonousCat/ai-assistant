> 更新：2026-11-17。入口 `jobs/send_market_digest.py`；领域 `skills/trend/digest.py`；绘图 `tools/market/chart_image.py`；传输 `tools/notifications/email.py`。

## 一、系统设计

每天上海时间18:00，由后端`jobs/market_digest_scheduler.py`调度，FastAPI lifespan负责启停。
生命周期入口沿用`jobs.scheduler.get_digest_scheduler()`，没有增加core/API到新任务模块的跨层导入。
邮件调用已有`deliver_once()`，数据库、绘图与SMTP放到`asyncio.to_thread`，等待/重试使用asyncio事件，保持HTTP可响应。

17点行情和18点邮件各自持有独立后台task；财务同步即使拖到18点后也不会阻塞发信。
邮件只读取本地库和已发布结果，不重新选参、不调用外部行情、不扫描新规则，不调用AI模型。
只需运行机器、网络与项目后端保持可用；关闭Codex或浏览器不影响已启动的后端。
原Codex18点自动任务已暂停，不再保留两个定时触发器。每日含休市日，休市日报注明最近完整交易日。

后端18点后重启会补查当天邮件：持久化回执已成功则跳过，不确定回执停止；只处理当天，不跨日补发旧名单。
数据/网络明确可重试时每10分钟等待至20点；20点后启动仅尝试一次，数据仍不齐则发送延迟说明。
关闭后端会停止等待和后续重试；已经开始的SMTP操作受自身超时控制，是否可重发由磁盘回执判断。

开关：`.env MARKET_DIGEST_ENABLED=true/false`优先于`config.yaml email_digest.enabled`（默认true），更改后重启后端。
管理员`GET /admin/scheduler-status`新增`mail_digest`：enabled/running/sending/next_run/last_run/last_result/owner。
沿用原有实时管理员权限校验，不新增公开接口。手动CLI仍保留作离线排查：

```powershell
.venv/Scripts/python.exe -m jobs.send_market_digest --send --wait
```

普通调用不发信：`.venv/Scripts/python.exe -m jobs.send_market_digest`生成HTML/EML/PNG本地预览。
实际发送正式日报必须显式带`--send`，18点前返回not_due。没有SMTP配置返回blocked，不能将预览成功当作发送成功。
用户显式要求测试时使用`--test-send`：任意时刻可用最近已发布快照，主题及正文标“测试”，清楚标注实际截止日，
发送记录放在独立`test/`目录，不占正式日报名额。不确定回执默认不重发；用户核对未收到后可显式使用
`--test-send --retry-uncertain-test`，保留不确定历史和原始EML再重试。部分已确认发送的信件不会重发。
测试参数不由18点后端任务调用，不能用于绕过正式日报的新鲜度校验。

邮件使用与看板一致的候选范围、评分、已发布参数和真实因子前复权，默认筛选**评分大于75分**的非ST、非退市标的。
成熟/被排除走势不会因高分再次成为候选。入场候选、观察候选分别分组，不提升观察记录的eligible字段。
分类优先context_pattern，其次原pattern/family，与前端一致；蓝↑趋势回调、紫■底部反转，未知不默认归为反转。

## 二、需求优化

- 深色卡片、总数与数据截止时间、评分汇总表、母趋势、风险距离、参考止损、筛选解释与检查结果。
- 一封HTML日报按「总览 → 入场/观察目录 → 入场卡片 → 观察卡片」阅读；总览显示两类候选及回调/反转数量，卡片按目录编号，每股独立显示日K和60F，不合成长幅总图。桌面最大820px、窄屏自适应；目录和返回链接使用邮件内锚点，不支持跳转的客户端可按编号浏览。
- 每股一张内嵌PNG（1540×990，128色调色板压缩，不改变K线数值、位置或分辨率）：原生日K及60F、M8/13/21、成交量、日K入场标记/60F观察标记；静态高清图无需外网图片服务器。
- 2026-11-17最终按用户要求日K显示滚动近5年，使用真实因子前复权、年/月时间轴；上市不足5年按实际历史展示。60F保留134根（原100根增加约1/3）；仍每股独立双周期图，保留全部候选，不自动重发旧邮件。
- 使用CID关联HTML与图片，正文为兼容邮件客户端的table与内联样式，并提供纯文本备选和UTF-8 BOM CSV。
- 本地HTML将图片转为data URI方便离线查看，发送邮件使用CID；邮件不依赖JavaScript或SVG。
- 每期固定一封包含完整名单、逐股图表和CSV，不按股票数量或字节大小自动拆成多封。真实MIME超过8MiB时返回blocked，保留完整候选，不删股、不发送部分名单。历史多部分缓存只按原回执续传，已成功部分不重发。
- 数据未齐时每10分钟等待/重试，最多到当日20点；届时仍缺数据只发延迟说明，不夹带旧股票名单。

## 三、问题

| 问题 | 根因 | 处理 |
|---|---|---|
| 同一日报收到三封且内容看起来重复 | 固定每20只拆分，47只被拆成20/20/7；标题和摘要却都显示全期47只，未体现本封范围 | 按用户要求固定一封，取消自动拆分；真实超限则停止，保留旧批次回执，升级不重发已成功邮件 |
| 每日发信依赖Codex客户端 | 调度挂在Codex，项目服务运行不足以触发邮件 | 迁入后端独立asyncio任务，18点启动/当天补漏/磁盘回执去重，暂停原Codex任务 |
| 仅有收件邮箱无法自动投递 | 缺少认证发件通道 | 独立系统邮箱SMTP，客户端授权码仅存本地.env；收件邮箱不需授权 |
| 18点误把昨日结果当今日 | 只看存在快照或全局最大日期 | 检查应有交易日、两个周期截止、完整行情任务及其snapshot run_id一致 |
| 高分观察被当作买入 | 评分门槛没有区分信号状态 | 与看板候选范围一致，入场/观察分组，原eligible不修改 |
| SMTP断线后重复投递 | DATA可能已被服务器接受但回执丢失 | 持久化sending/sent/uncertain；不确定停止自动重发，提示核对收件箱 |
| 多部分邮件重试重复前半段 | 没有逐部分记录回执 | 锁+逐部分保存Message-ID与回执，只重试明确未接受的部分 |
| 进程在发送后崩溃 | 本地sending记录尚未转sent | 下次认定uncertain，保守停止，不宣称严格的exactly-once投递 |
| 损坏发送记录导致重发 | 非法JSON被当作首次运行的空状态 | 发送记录严格读取，损坏立即停止；缓存收件人与Message-ID必须匹配记录 |
| 图文邮件上传中断却统一标为回执不确定 | 缺乏DATA阶段和结束标记证据，原大图邮件约2.2MB | PNG调色板压缩至整封约682KB、16KiB分块、连接/认证30秒与正文/回执120秒分离；明确未写入结束标记的失败允许安全重试，尾块或回执不确定仍停止 |
| 已生成完整EML的安全重试仍卡在数仓读取 | 每次重试都先读取已发布快照，即使parts已冻结且发送无需重算 | 仅首次生成邮件才读取快照/检查数据，已有缓存沿用原Message-ID、收件人校验与SMTP回执，不依赖数仓恢复 |
| 图中价格标签与刻度/下一周期标题碰撞 | 单图右边距及子图间距不足 | 调整右侧价格牌与子图间距，真实PNG目视复核 |

## 四、处理方案

发件人推荐专用QQ/163邮箱，免自建邮件服务器。已支持SSL 465/994及STARTTLS；禁止明文、不校验证书等模式。
163需在邮箱内开启SMTP并获取客户端授权码，不使用邮箱登录密码。
参考[SMTP与授权码配置说明](https://support.huaweicloud.com/usermanual-roma/roma_03_5051.html)。

以下只作占位示例，实际收发地址和授权码写入不纳入Git的`.env`：

```dotenv
MARKET_DIGEST_TO=reader@example.com
MARKET_DIGEST_MIN_SCORE=75
MARKET_DIGEST_OBSERVATIONS=true
SMTP_HOST=smtp.163.com
SMTP_PORT=994
SMTP_SECURITY=ssl
SMTP_DATA_TIMEOUT=120
SMTP_USER=sender@163.com
SMTP_FROM=sender@163.com
SMTP_PASSWORD=CLIENT_AUTHORIZATION_CODE
```

同一SMTP适配器也可配置[Resend SMTP](https://resend.com/changelog/smtp-service)：user=resend、password=API Key、from=已验证域名地址。
正式发送要求[自有域名验证](https://resend.com/docs/dashboard/domains/introduction)；
[免费额度](https://resend.com/pricing)为每月3000封、每日100封（2026-11-16核实）。目前没有创建第三方邮件服务账号或订购服务。

静态绘图依赖matplotlib、numpy与Pillow，当前项目虚拟环境已具备，无额外安装步骤。图表是高清静态PNG，邮件内不提供前端的交互缩放。

输出均在`output/market/email_digest/`：预览按snapshot run_id归档，正式发送按本地发送日和收件配置指纹归档。
正式信件在发送前全部生成，EML包含固定Message-ID；重试复用已生成文件，不能混合不同快照。
锁与JSON原子写复用`core/local_state.py`，行情更新工具同样复用此基础设施。
SMTP发送按握手、正文、回执分段，记录脱敏错误类型及传输阶段；未完成结束标记前的失败与回执未知分开处理。
发送成功仅表示SMTP服务器接受，不能证明邮件最终进收件箱；首次实际投递后需由收件人检查收件箱/垃圾箱。

认证失败、无效收件人或明确5xx拒绝停止本轮，网络与4xx明确未接受可重试；回执不确定不自动重发。
日志/自动化摘要只返回脱敏状态和异常类型，不输出授权码或SMTP服务器原始回包。
缺授权码时可查看预览，但不得声称每日实际投递已经就绪。
