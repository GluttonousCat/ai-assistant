# 全项目技术审核与第一轮优化

> 日期：2026-11-12。范围：架构横向审核、核心链路重点审查及可回归验证的修复；不是逐行完备性证明。

## 一、系统设计

平台由行情财务数仓、研报下载与提取、Agent 问答三条主链构成。
HTTP 经 api 进入 harness/skills，工具负责查询、解析和抓取，storage 管理数据库资源，core 提供配置与日志。
前端使用 React/Vite，后端托管构建产物。对话通过 POST SSE 接收阶段、工具结果、表格和回答。

本轮覆盖 api/core/harness/skills/tools/storage/jobs 七个目录的 187 个 Python 文件语法检查，
重点阅读鉴权、路由、配置、连接池、会话、SQL guard、模型工厂、调度生命周期、数仓 DDL、前端壳和对话组件。
研究生产线、产业链、MCP 通过现有测试回归；未对每一个业务文件做逐行语义审计。

## 二、需求优化

1. 对话成为持续研究工作台：标签页内多会话、独立草稿、复制、停止、错误重试、中文输入法保护、移动端布局。
2. 先处理会影响数据正确性与权限边界的问题，再处理样式和注释。
3. 数据库保留上游字段契约，新增对象遵循明确命名与迁移规则，见 [数据库命名](schema_naming.md)。
4. 保持模型选择集中配置，保留已有财务口径、图表和只读工具约束。

## 四、处理方案

对话拆出 `useChatWorkspace` 与 SSE parser，单个标签页最多保存 20 个会话、每会话 100 条消息，
浏览器配额失败显示提示；草稿与记录按账号区分，切换平台页时刷盘，流式更新节流写入。
保留原图表识别和表格呈现，研究过程默认折叠，正文采用更宽松的阅读行距。
历史 Markdown 与结构化结果使用 memo，避免每个文本分块都重新解析所有历史与重建图表规格。
停止/断流保留已生成文本，错误独立显示并可重试；输入过程中可准备下一条问题。

后续工作按风险与依赖排序：

| 顺序 | 待完成事项 | 验收条件 |
|---|---|---|
| 1 | 数据访问边界收敛：现有 skills/API 中仍有直接 PgClient 使用 | 将业务查询移入 storage 仓储，保留 API/工具契约与回归测试 |
| 2 | 真正 token 流与协作取消：当前 harness 最终回答仍按已生成全文分块 | 首 token 延迟有基线；模型、工具、任务状态能一致终止；避免停止后误报成功 |
| 3 | 持久会话、服务端删除与并发轮次隔离 | PG 为真相源，用户所有权检查、分页、TTL/保留期、同会话请求串行契约完整 |
| 4 | 数据库迁移版本化与查询计划 | 获取真实行数、索引和 EXPLAIN 后决定 DDL；提供升级、回滚和兼容验证 |
| 5 | 单独数据库只读角色及 SQL 能力收敛 | AST + 事务只读 + 最小授权共同生效，验证函数调用与资源耗尽边界 |
| 6 | 配置初始化及连接池恢复并发测试 | 不关闭仍在使用的连接；配置加载失败可恢复，启动和重连行为确定 |
| 7 | 研报调度/OCR 长任务故障注入与全链路观测 | 断网/重启恢复、幂等、队列容量和耗时指标可量化 |

当前停止按钮中断 HTTP 消费，已进入 `asyncio.to_thread` 的同步调用不能被强杀；
本地会话列表也不改变服务端 30 分钟 TTL 和重启丢失上下文的设计。
本轮没有执行生产 DDL、重命名物理表或重启正在运行的后端。

## 五、验证记录

- Python：使用项目 `.venv`；`pytest api storage harness skills tools -q` 共 367 项通过（1 条依赖弃用告警）。系统 Python 因缺 matplotlib 收集失败，已确认项目虚拟环境具备依赖。
- 前端：`npm test` 的 3 个协议测试通过；`npm run build` 通过；`npm run lint` 无错误，保留原有 Fast Refresh 混合导出告警。
- 浏览器：使用临时本地模拟流 fixture，检查回复、折叠过程、新建/切换会话、停止生成、独立草稿与刷新恢复；截图在 `output/qa/chat-workspace.png`。模拟回答不构成模型质量或实时数据正确性验证。
- 未进行真实 LLM、爬虫、OCR 和数据库迁移联调；外部服务故障与负载性能不在本轮测试结论内。
