# 分钟行情、指数成分池与新闻快照接入方案

> 核实日期：2026-11-12。状态：选型与本机只读探测完成，未新增生产采集任务、执行 DDL 或购买服务。

## 一、系统设计

需求范围：沪深300、上证50、中证500、中证1000、中证2000的成分股并集。
名义席位合计 3850，股票按代码去重，实际名单与覆盖数量以供应商成分数据为准。
成分股分钟线与指数本身的分钟线是不同数据；BaoStock 文档不提供指数分钟线，不能由成分股 OHLC 简单平均替代指数行情。

数据路径：供应商适配器（tools）→ 同步任务（jobs）→ 仓储与质量检查（storage）→ API/MCP → 前端。
领域分析由 skills 使用同一份数据，不在每次聊天时实时抓数，也不让浏览器直接请求供应商。

## 二、需求优化

- 可接受免费盘后分钟数据，优先获得 15/30/60 分钟，也保留最初提出的 5 分钟需求。
- 付费实时源先比较成本、批量容量、数据完整性和延迟，再决定开通。
- 新闻按快讯流与可回溯快照设计，同时服务股票、产业链及事件研究。

## 三、问题

| 问题 | 影响与处理原则 |
|---|---|
| 分钟周期与实时性混淆 | 60 分钟 K 线可以盘后才提供；必须单独记录数据可用时间 |
| 只保存当前指数成分 | 历史研究有幸存者偏差；保留成分快照日期、采集时间与来源，未知历史不得伪造 |
| 多供应商数量、复权和时间口径不同 | 统一股/元、不复权底座、交易时区、起止时间和闭合状态；保留 source 与修订信息 |
| 免费快讯仅返回滚动窗口 | 断采可能永久漏新闻；前端必须显示数据缺口，不能把空响应当作无新闻 |
| 付费接口也不是稳定性的证明 | 先验证实际延迟、缺数、回补和限额，开通前不承诺可用性 |

## 四、处理方案

### 4.1 来源与成本

以下为官方个人用户公开报价，分钟/新闻均独立于 Tushare 积分权限；最终按开通页面确认。

| 来源 | 能力 | 公开价格/限制 | 拟用位置 |
|---|---|---|---|
| BaoStock | 免费股票 5/15/30/60 分钟历史；官网注明交易日 20:00 完成分钟入库 | 免费；历史边界和标的覆盖要实测；不作为盘中实时源 | 免费盘后候选主源 |
| Tushare 历史分钟 | 1/5/15/30/60；权限表注明历史从 2009 年起 | 2000 元/年 | 免费源验证不通过时的盘后替代 |
| Tushare 实时分钟 `rt_min` | 1/5/15/30/60；周期闭合后生成，支持多代码 | 1000 元/月；权限表注明每分钟500次、单次300家公司，接口页另有1000行限制 | 有盘中需求时的候选主源 |
| Tushare `rt_min_daily` | 单股当日盘中分钟历史 | 同实时分钟权限 | 断线恢复与当日回补 |
| Tushare `news` | 多媒体来源快讯，可按时间取历史 | 1000 元/年；文档注明每小时第50分钟更新 | 归档/回补，不作低延迟快讯源 |
| AKShare→东方财富快讯 | 最近200条，标题/摘要/时间/链接 | 免费获取路径，无完备性承诺 | 本机已跑通，第一阶段新闻主源 |
| AKShare→财联社电报 | 官方文档注明当前网页接口适配，最近20条 | 免费获取路径，窗口更短 | 新闻补充源，需单独验证网络与版本 |
| QMT/xtdata | 订阅分钟、历史读取与本地缓存 | 无统一可核实零门槛报价；依券商/终端/行情权限确认 | 用户已有接入条件时评估 |
| 米筐 RQData | 历史及实时分钟，Python/WebSocket 能力 | 本轮未核实统一公开套餐价，需按权限询价 | 多标的实时服务备选 |

建议第一阶段优先验证 BaoStock，免费新闻先用东财、财联社补充。盘后数据若不能稳定到齐，比较 Tushare 历史分钟；不因已有积分而假定分钟权限已开通。
如后续需要实时，Tushare 实时分钟按整年连续购买折合 12000 元，历史权限/新闻权限另计；不假定实时权限包含所有历史和指数数据。

### 4.2 存储、周期与质量

新表建议放现有 `stock` 域：`index_membership_snapshot`、`intraday_bar`、`data_sync_state`；
新闻独立 `news.article`、`news.article_revision`、`news.article_entity`，不塞进研报表。
以上仅为设计，本轮不执行建表或迁移。

分钟线采用 5 分钟不复权数据为可选底座，按早/午交易时段合成15/30/60分钟；
首次上线必须逐根对照来源原生周期，确认集合竞价、午休、停牌、零成交、收盘和端点归属。
缺少子 bar 的聚合结果标记不完整，不生成伪造完整 K 线；进行中 bar 与闭合 bar 分开。
保留 `bar_start`、`bar_end`、`interval_minutes`、`source`、`fetched_at`、`is_final`，交易时区统一 Asia/Shanghai。
原始来源数据与规范数据分开存放，多源修正通过明确优先级和版本处理，不能无声覆盖或拼接。

容量估算：假设3800只、每日240分钟连续交易，5分钟约18.24万行/日，四周期共约28.88万行/日；
按250个交易日约7220万行/年（不计停牌、竞价及来源差异）。
先做真实样本容量/查询基准，再决定 PG 月分区、索引与历史冷存储，不按猜测分表或引入新数据库。

新闻保存原始来源、发布者、来源ID/链接、发布时间、首次采集时间、内容哈希和修订版本。
同一新闻的多次采集不反复入库，跨媒体转载保留来源关系，不冒充独立证据。
研究查询用首次可用时间限制信息集，避免用之后补抓的新闻制造历史先知；全文存储/展示范围按来源许可确定。
去重后再做股票/产业链映射和按需摘要，避免每条新闻都触发昂贵模型调用。

### 4.3 上线顺序与验收

1. 同步并保存五组指数的实际成分并集及日期；先抽取分散板块/流动性的50只作试运行，再覆盖整个池。
2. 免费分钟源连续交易日探测：验证可达性、数据可用时间、数量、端点、复权、停牌及重试回补。
3. 接入新闻快照：重叠窗口、去重、来源切换、时间新鲜度和断采缺口可见。
4. 增加行情/新闻查询 API 与只读 MCP，再把分钟周期切换和新闻时间线接入前端。
5. 实时源试用验收后才切主源，记录闭合延迟、缺数率、恢复耗时和实际调用成本。

## 五、验证记录
