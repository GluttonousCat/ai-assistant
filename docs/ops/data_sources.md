# 分钟行情、指数成分池与新闻快照接入方案

> 核实日期：2026-11-12。状态：选型、取数验证与2026年60F五指数成分并集入库已完成；未购买服务，新闻接入待实施。

## 一、系统设计

需求范围：沪深300、上证50、中证500、中证1000、中证2000的成分股并集。
名义席位合计 3850，股票按代码去重，实际名单与覆盖数量以供应商成分数据为准。
成分股分钟线与指数本身的分钟线是不同数据；BaoStock 文档不提供指数分钟线，不能由成分股 OHLC 简单平均替代指数行情。

数据路径：供应商适配器（tools）→ 同步任务（jobs）→ 仓储与质量检查（storage）→ API/MCP → 前端。
领域分析由 skills 使用同一份数据，不在每次聊天时实时抓数，也不让浏览器直接请求供应商。

## 二、需求优化

- 可接受免费盘后分钟数据，优先获得 15/30/60 分钟，也保留最初提出的 5 分钟需求。
- 付费实时源先比较成本、批量容量、数据完整性和延迟，再决定开通。
- 新闻按快讯流与可回溯快照设计，同时服务股票、产业链及事件研究。

### 4.2 存储、周期与质量

新表建议放现有 `stock` 域：`index_membership_snapshot`、`intraday_bar`、`data_sync_state`；
新闻独立 `news.article`、`news.article_revision`、`news.article_entity`，不塞进研报表。

分钟线采用 5 分钟不复权数据为可选底座，按早/午交易时段合成15/30/60分钟；
首次上线必须逐根对照来源原生周期，确认集合竞价、午休、停牌、零成交、收盘和端点归属。
缺少子 bar 的聚合结果标记不完整，不生成伪造完整 K 线；进行中 bar 与闭合 bar 分开。
保留 `bar_start`、`bar_end`、`interval_minutes`、`source`、`fetched_at`、`is_final`，交易时区统一 Asia/Shanghai。
原始来源数据与规范数据分开存放，多源修正通过明确优先级和版本处理，不能无声覆盖或拼接。

容量估算：假设3800只、每日240分钟连续交易，5分钟约18.24万行/日，四周期共约28.88万行/日；
按250个交易日约7220万行/年（不计停牌、竞价及来源差异）。
先做真实样本容量/查询基准，再决定 PG 月分区、索引与历史冷存储，不按猜测分表或引入新数据库。

新闻保存原始来源、发布者、来源ID/链接、发布时间、首次采集时间、内容哈希和修订版本。
同一新闻的多次采集不反复入库，跨媒体转载保留来源关系，不冒充独立证据。
研究查询用首次可用时间限制信息集，避免用之后补抓的新闻制造历史先知；全文存储/展示范围按来源许可确定。
去重后再做股票/产业链映射和按需摘要，避免每条新闻都触发昂贵模型调用。
