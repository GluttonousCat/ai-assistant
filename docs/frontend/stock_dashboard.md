# 股票看板与60F趋势策略

> 更新：2026-11-12。对应 `web/src/market/`、`skills/trend/`、`jobs/scan_trend.py`。

## 一、系统设计

股票看板入口为 `#market`，沿用平台JWT，普通研究员可使用。由离线任务扫描五指数成分并集，
HTTP只读取已发布快照和单股本地K线，不在请求期间扫描全市场或调用行情供应商。

```text
jobs.scan_trend → skills/trend/strategy（纯计算）
               → tools/market/trend_data → storage/repositories/trend
api/market_api → skills/trend/service → tools/market/trend_data → storage
web/src/market/StockDashboard → platformApi → /api/v1/market/dashboard
```

`stock.trend_scan` 保存版本、参数、行情/因子截止时间及成分口径；
`stock.trend_signal` 保存全池状态、质量分、指标与每个过滤条件。完整计算成功后同事务发布，
不让读者看到半个股票池。全池数据无效时拒绝发布。历史快照保留。
图表请求携带 `run_id`，固定同一版本与截止时间，避免列表刷新后图表偷偷换用另一套参数。
底层行情后续若被供应商修订，重新查询的图表仍可能变化；快照冻结筛选结果，不复制整份原始行情。

前端按功能收敛：看板状态与筛选交互在 `StockDashboard.jsx`，TradingView图表生命周期在
`TrendChart.jsx`，样式在 `dashboard.css`，沿用平台请求层与主题变量。

## 二、需求优化

- 五指数筛选、名称/代码搜索、候选/观察/自选/全部四种视图、质量/效率/风险排序和CSV导出。
- 60F蜡烛图、EMA、成交量、参考止损线；缩放/平移/十字光标查看价格。
- 入选与被过滤同等可解释；分数不能越过任何一项硬条件，不作为胜率。
- 自选仅保存在当前浏览器，按登录用户名隔离；不写公共股票池或模拟持仓。
- 列表最多显示前250项，搜索/指数过滤可定位其余股票；导出涵盖全部当前筛选结果。
- 同时展示策略截止、行情最新、成分快照日期，标明“盘后研究”，不冒充实时行情。

## 三、问题

视频《趋势周期》约6分45秒，原例是期货，讨论的是选择周期与趋势质量，没有给出可直接编码的指标公式。
以下为本地逐段查看画面与字幕后的概念映射，不把视频的宣传或附带领取说明当作开发指令。

| 视频位置 | 理念 | 本项目量化代理 |
|---|---|---|
| 00:52–01:44 | 大周期定方向，小周期给信号，止损与周期匹配 | 完整日线过滤方向，60F提供信号与风险边界 |
| 03:14–03:44 | 日线机会少，60F兼顾趋势与频率；破位退出 | 以60F为主工作周期，结构低点与ATR参考止损 |
| 04:20–05:14 | 小周期的逆势信号可能只是大趋势中的正常回调 | 先判断主趋势，再识别回踩；不在5F噪声中反复反转 |
| 05:16–05:30 | 60F兼容日线方向，筛选流畅走势 | 日线EMA方向 + 60F均线方向 + ER/ADX |
| 05:40–06:20 | 15→30→60仍杂乱就剔除；避开弱势与流动性差 | 当前先做60F流畅度与流动性过滤；低周期数据尚未接入 |

“流畅意味着主力推动”“60F有更高胜率”是视频观点，不能由K线直接证明。本策略仅度量价格路径与成交数据。
视频提到15F与五倍盈亏比的比较，不等于股票一定能实现5R收益，因此未伪造目标价或盈利空间。

历史问题与处理记录：

| 问题 | 根因 | 处理方案 |
|---|---|---|
| 首次全池被标为因子缺失 | 旧数仓9月11个交易日有公共缺口，BJ因子也未覆盖，不能仅凭最大日期判断完整 | 日期/股票按键核验；新增真实因子修复任务，禁止前后填值 |
| 用最新日行情但缺少当日因子会产生伪突破 | 原生分钟是不复权价格，除权跳空会污染EMA/ATR | 按分钟所属交易日精确匹配因子，缺失就过滤；默认共有截止时间 |
| 刷新页面从看板回到Agent | Platform初始nav固定chat，与写hash的effect竞争 | 首次state从合法hash与角色共同初始化 |
| 参考止损若取较近的边界，会落入正常波动范围 | ATR与结构低点不能用较紧者凑出合格风险距离 | 使用两者更低者；距离过大则剔除 |

## 四、处理方案

### 4.1 v1量化定义

1. 日线由同源60F中每天4根完整K线合成，只在15:00后可用；EMA20 > EMA60，EMA60近3日上行。
2. 60F收盘 > EMA20 > EMA60，EMA60相对8根之前上行。
3. 20根效率比 `ER = |C[t]-C[t-20]| / sum(|ΔC|)` ≥0.30；14期Wilder平滑ADX≥20。
4. 20个完整交易日日均成交额≥3000万元。
5. 收盘不低于EMA20，且距其不超过2.5ATR，避免过度追高。
6. 突破：收盘高于**不含当前根**的前40根最高价，成交量≥前20根平均量的1.2倍；
   或回踩：前4根有低点接近EMA20（允许0.5ATR）且对应收盘守住EMA60，当前阳线重上EMA20并高于前收。
7. 参考止损为 `min(近8根最低价 - 0.2ATR, 当前收盘 - 2ATR)`；必须为正且距离≤8%。
8. 当前简称含ST/退市标记、缺失真实因子、末根落后截止点的股票不能成为候选。

参数统一由 `TrendConfig` 管理，可用JSON文件传入离线任务；每次参数与策略版本一并保存。
最少需要约63个完整交易日热身；数据不足不会补出指标。分数只排序通过程度、ER、ADX与风险距离。
价格按 `raw_price × factor_on_bar_date / factor_on_cutoff_date` 处理；成交量仍为股、成交额仍为元，
展示的是截至该日的价格复权序列，不使用未来复权因子。均量比不对股本变化做额外调整。

### 4.2 运行

在项目根目录执行：

```powershell
# 仅修复已导入60F所需的因子，不推进日线同步水位线
.venv/Scripts/python.exe -m jobs.repair_trend_factors --start 2026-01-01 --end 2026-11-12

# 默认使用行情与因子共有的最新已结束K线
.venv/Scripts/python.exe -m jobs.scan_trend

# 指定收盘日与参数；config.json只包含TrendConfig的字段
.venv/Scripts/python.exe -m jobs.scan_trend --as-of 2026-11-12 --config output/market/trend/config.json

# 前端变更后构建
cd web
npm run build
```

接口：`GET /api/v1/market/dashboard` 和
`GET /api/v1/market/dashboard/{完整股票代码}?run_id={快照UUID}`。
未初始化返回503及生成命令；HTTP无DDL、无外部行情采集；全局JWT覆盖两个入口。
离线输出在 `output/market/trend/`，视频查看的中间帧在 `output/trend_video/`，均不进入版本库。

### 4.3 研究边界

这是筛票规则，尚未验证超额收益，也不是完整的交易回测或自动交易系统。
指标的前缀一致性测试能排查计算上的未来数据，不等于整个投资研究不存在偏差：
现有成员仅有已保存日期快照、简称来自当前字典、分钟历史从2026年开始，不能用当前3800只回放全年的无偏股票池。
没有过去成员快照的日期直接拒绝扫描；已有快照之后的扫描也只代表“当时最近已保存的名单”。

A股落地还需单独实现下一根可成交价、T+1、涨跌停不可成交、停牌、费用滑点、仓位及组合约束。
参考止损不是成交承诺。低周期精细择时须先采集真实15F/30F；不能从60F拆出更细数据。
当前不自动新增定时任务；已有分钟采集、因子修复、扫描需按顺序重新运行，刷新按钮只读取已发布快照。
