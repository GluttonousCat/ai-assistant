# 股票行情与60F/日K趋势策略

> 更新：2026-11-17。对应 `web/src/market/`、`skills/trend/`、`jobs/scan_trend.py`。

## 一、系统设计

`信号跟踪`复用`stock.trend_scan`/`stock.trend_signal`的已发布历史名单，不新增表、不回放当前规则伪造旧日入选。
`episodes.py`把连续入选合为机会轮次，默认跟踪中，满20个交易日归档；每日快照原样保留在按日复盘。
`chart_history.py`独立加载5年展示行情，叠加原策略时间窗的冻结标记，扩展显示不扩展策略计算输入。
`intraday.py`复用`mtf.minute_context`生成独立盘中观察；采集及扫描分别由`cache_intraday_prefix`、
`scan_intraday_watch`运行，原子发布`output/market/intraday_watch/latest.json`，不写正式扫描表或完整日检查点。
调用链为`api/market_api → skills/trend/tracking → tools/market/trend_data → storage/repositories/trend`，
列表批量读取本地原生日K及真实因子；K线详情固定旧run_id的参数，但行情延伸到当前已完成收盘日。
只按上海时间15点界限读取完整日K，不调用外部供应商、LLM或订单服务；重IO在线程运行。
每个入选日采用最后一次发布快照，返回原版本与实际发布时间；回填快照不表示当日已能取得该信号。

`parent_context.py`新增独立的日K母趋势标注（daily-parent-wave-context-v1），将母趋势与局部触发分开：同一个60F止跌反转，在保留上涨结构的日K波段里可解释为回调再起。原始pattern、eligible、分数、检查和止损字段保留，派生context_pattern用于展示，不把新分类冒充旧策略的新入场信号。双周期单股图复用已有原生日K，离线扫描及`jobs.annotate_trend_context`为列表增加相同背景；没有新增行情供应商请求或DDL。

v9有序结构仅在量化研究页发布固定对照：60F启动—推进—缩量回调—再转强、低点测试反转，附已确认支撑的结构持有；不覆盖本页旧快照或把未重算的历史信号改名。量化成交可查看推进起点、高点及第几次回调，主方案仍需由回测证据评估。

2026-11-14口径澄清：用户的“日K进场”指无法盯盘时的日级执行安排，不要求日K再提供转强形态。新增`v8`主板研究在60F上完成底背离/回调识别，盘后汇总、次日执行；详见[量化研究](../agents/quant_backtesting.md)。本页旧v5—v7历史快照仍按其原始日K确认规则解释，不用新规则改写旧信号，也不把研究结果冒充已经发布的全池快照。

股票行情入口为 `#market`（原名股票看板），沿用平台JWT，普通研究员可使用。由离线任务扫描当前非ST上市股票（沪深三板及原有北交所），保留五指数子集筛选，
HTTP只读取已发布快照和单股本地K线，不在请求期间扫描全市场或调用行情供应商。

```text
jobs.scan_trend → skills/trend/strategy（纯计算）
               → tools/market/trend_data → storage/repositories/trend
api/market_api → skills/trend/service → tools/market/trend_data → storage
web/src/market/StockDashboard → platformApi → /api/v1/market/dashboard
```

`stock.trend_scan` 保存版本、参数、行情/因子截止时间及成分口径；
`stock.trend_signal` 保存全池状态、质量分、指标与每个过滤条件。完整计算成功后同事务发布，
不让读者看到半个股票池。全池数据无效时拒绝发布。历史快照保留。
图表请求携带 `run_id`，固定同一版本与截止时间，避免列表刷新后图表偷偷换用另一套参数。
底层行情后续若被供应商修订，重新查询的图表仍可能变化；快照冻结筛选结果，不复制整份原始行情。

前端按功能收敛：看板状态与筛选交互在 `StockDashboard.jsx`，TradingView图表生命周期在
`TrendChart.jsx`，样式在 `dashboard.css`，沿用平台请求层与主题变量。
图上展示简单移动平均M8/M13/M21。当前v6追踪60F低位早期反转，用相同均线辅助确认趋势，并以原生日K确认入场。
旧v4快照仍使用其冻结的EMA20/60策略参数，图表均线与其旧信号的口径分开标注，不改写历史结果。
图表请求/取消/有界缓存由`useStockChart.js`管理；时间归一、历史修订判别与视野锚点在`chartData.js`。
图表与序列只在组件挂载时创建，切换股票/周期更新数据；首阳标记与止损线独立更新。
增量尾部用`series.update`，历史复权/修订则整批替换，避免旧价格遗留。
十字光标仅在指向另一根K线时按动画帧刷新提示，日期格式器复用；布局交给图表autoSize。
每页缓存最近20组股票/周期/快照数据，20组时间视野；刷新绕过旧缓存，切换会取消过时请求。
同图刷新保留K线，换图未命中缓存时只显示覆盖层，不卸载画布；“回到最新”可重置缩放与价格自适应。
时间视野按实际K线时间锚定，历史窗口滑动后不误看成另一段日期。

## 二、需求优化

- 「盘中观察」独立显示观测截止、日K背景截止、采集覆盖、今日新起点/延续观察，支持回调/反转筛选。本轮仅10:30/11:30两根，之后K线即使供应商已返回也剔除；缺任一根不参与。全部eligible=false，不把上午日K当完整日确认。
- 沿用已发布配置的60F早期反转、M8修复、流动性、偏离及风险门槛，参考位取结构低点外与至少1.25ATR的更低者。盘中排序最高80分，未计完整日K转强20分，与盘后100分分开。母背景只用上一完整日，因子按交易日匹配，两图统一当天因子基准以处理除权。

- 股票行情新增「趋势筛选 / 信号跟踪」页签，跟踪模块按需加载。默认跟踪机会轮次，提供跟踪中/已归档/按日复盘；按日视图保留日期切换，展示≥60分入场与观察候选，保留当时评分、分类及筛选理由。
- 同股、同策略版本/参数、同60F起点在连续已有扫描日出现时合为一轮；升级入场只记录确认日期，不改变首次日期、评分及收益基准。已有扫描日中断后再入选、起点或策略改变则新建一轮并注明原因；缺失整天扫描不假定退出。每轮展开查看每日评分/状态，满20个交易日自动归档，离开候选的轮次也继续统计，避免幸存者筛选。观察范围为最近120个已有扫描日，窗口首日已有记录只称窗口内首见。
- 跟踪列表可搜索代码/名称、筛选当时状态、趋势回调/底部反转和板块，按当时评分或最新变化排序；展示微型走势、T+1/3/5/10交易日收盘变化、最近有效行情日期、入选后最高/最低价相对入选日收盘变化。表内滚动，页头统计明确有效样本数量。
- 从入选日收盘起，以`close_t × adj_factor_t / (close_0 × adj_factor_0) - 1`计复权价格变化；最高/最低使用后续日K high/low相同因子比例，排除入选日高低。这些是观察指标，不是实际交易收益、胜率或峰值回撤。
- 交易日按SSE日历定位，不以个股下一根K线代替次一交易日。未到期、缺行情/因子（含停牌）、缺基准分别提示；缺失不填零、不顺延，微型走势在缺失处断开，区间极值只计有效行情。最新均值只计有后续报价的股票，各股可能存在不同的最近有效日。
- 跟踪K线默认显示近5年日K，可切60F；支持近3月/1年/5年缩放及定位入选日，金色箭头固定标记本轮首见，之后行情不再显示用旧参数新算出的入场信号。历史列表状态仍冻结，复盘图表使用最新真实因子前复权；行情或因子被修订时图表与价格统计可更新。同股跨日重复仅在按日视图完整保留；同股不同轮次仍单列，不视为独立组合交易。
- 网页与邮件的日K均使用滚动5年原生日K，上市不足5年显示实际历史；额外70个日历日用于均线预热，展示不再截断为1000根。历史OHLC/M8/13/21与原策略标记按日期合并，冻结策略仍从原start计算；不补造早年交易信号。5年图使用更细最小间距，价格轴重排后重新对齐范围，并用请求序号避免旧范围覆盖新股票/周期。

- `MarketFreshness.jsx`区分库内日K/60F最新记录与已发布快照截止，显示后台采集/重算进度。每60秒轻量检查`/api/v1/market/freshness`，新run_id出现才刷新列表与图表；页面隐藏时暂停、恢复可见立即检查。规则版本提示不再将沿用旧规则误写成行情未更新。每日自动链路与审计见[行情定时更新](../ops/daily_sync.md)。

- 显示“日K母趋势背景＋局部触发”，如“日K上涨结构内回调 · 局部止跌反转”。日K MA13/21用于确认此前的上升结构，调整期间保留波段锚点，支持20余根日K的回调；局部MA走弱或局部反转不自动等于日K底部反转。观察与入场状态仍分开。
- 趋势回调使用蓝色↑，底部反转使用紫色■：股票列表、详情标题、K线图例/标记及量化成交/未平仓统一展示。确认标记分别为箭头/方块，观察仍为圆点，灰色起势背景保持非交易语义。底部反转是机会分类，不等于已确认长期底部。
- `web/src/opportunities.js`集中展示映射，`OpportunityBadge.jsx`复用标签；优先后端pattern/family，仅在缺失时用明确的旧再起/反转观察字段兼容。未分类不默认当作反转。机会筛选使用同一映射，CSV新增“机会分类”，保留原有细分类型。此改动不重算信号或改写历史筛选规则。
- 五指数筛选、名称/代码搜索、日K入场候选/观察/自选/全部视图；旧v4另保留首阳/再起视图。
- K线图内提供日K/60F切换，默认显示日K；切换只改变图表。当前列表/统计/解释/CSV固定为“60F趋势→日K入场”，
  60F图只展示趋势背景，日K图标注入场；日K初始止损可在同尺度60F图参考，明确标注周期。旧v4仍保持原60F列表口径。
  旧快照没有日K时图表回退60F。支持蜡烛图、M8/13/21、成交量、缩放/平移/十字光标。
- 入选与被过滤同等可解释；分数不能越过任何一项硬条件，不作为胜率。
- 自选仅保存在当前浏览器，按登录用户名隔离；不写公共股票池或模拟持仓。
- 列表最多显示前250项，搜索/指数过滤可定位其余股票；导出涵盖全部当前筛选结果。
- 同时展示策略截止、行情最新、成分快照日期，标明“盘后研究”，不冒充实时行情。

## 三、问题

视频《趋势周期》约6分45秒，原例是期货，讨论的是选择周期与趋势质量，没有给出可直接编码的指标公式。
以下为本地逐段查看画面与字幕后的概念映射，不把视频的宣传或附带领取说明当作开发指令。

| 视频位置 | 理念 | 本项目量化代理 |
|---|---|---|
| 把回调再起与低位首阳混为排除关系 | v6.1专注低位窗口，成熟趋势回调被整体关掉 | V7将回调独立成机会、标记首次/后续轮次，仍检查实际结构风险 |
| 中科曙光10月16日缺口漏选 | 日K实体、M8收复及跨多日低点止损统一套用，60F首阳亦未满足旧实体位置门槛 | 独立缺口守稳结构，使用缺口相关失效位与60F早期修复条件；不按当天开盘回填信号 |
| 年初反转低点永久阻止数月后的新阴跌周期 | v6仅允许跌破原低点重置，误把所有更高低点都视为同一段 | v6.1新增持续下降周期退役条件；短暂回调不能重置。配置缺少reversal_cycle_reset的v6快照继续旧解释 |
| 已经反转一段后的阳线仍进入候选 | v5.1允许成熟60F多头，未限制低位反转原始起点 | v6只接纳阴跌/深坑前置结构与早期窗口，保留起点跨越局部回调；观察与日K入场分开 |
| 00:52–01:44 | 大周期定方向，小周期给信号，止损与周期匹配 | 完整日线过滤方向，60F提供信号与风险边界 |
| 03:14–03:44 | 日线机会少，60F兼顾趋势与频率；破位退出 | 以60F为主工作周期，结构低点与ATR参考止损 |
| 04:20–05:14 | 小周期的逆势信号可能只是大趋势中的正常回调 | 先判断主趋势，再识别回踩；不在5F噪声中反复反转 |
| 05:16–05:30 | 60F兼容日线方向，筛选流畅走势 | 日线EMA方向 + 60F均线方向 + ER/ADX |
| 05:40–06:20 | 15→30→60仍杂乱就剔除；避开弱势与流动性差 | 当前先做60F流畅度与流动性过滤；低周期数据尚未接入 |

“流畅意味着主力推动”“60F有更高胜率”是视频观点，不能由K线直接证明。本策略仅度量价格路径与成交数据。
视频提到15F与五倍盈亏比的比较，不等于股票一定能实现5R收益，因此未伪造目标价或盈利空间。

| 趋势回调与底部反转在图上不易区分 | 不同类型共用同色确认箭头，列表强调状态，回测缺失类型默认反弹 | 蓝色箭头/紫色方块与中文类型同时标注，观察/背景分开；前端集中映射用于列表、筛选、图表与回测，缺失类型显示待识别 |
| 首次全池被标为因子缺失 | 旧数仓9月11个交易日有公共缺口，BJ因子也未覆盖，不能仅凭最大日期判断完整 | 日期/股票按键核验；新增真实因子修复任务，禁止前后填值 |

| 刷新页面从看板回到Agent | Platform初始nav固定chat，与写hash的effect竞争 | 首次state从合法hash与角色共同初始化 |

## 四、处理方案

### 2026-11-17 历史信号跟踪

后续增加`GET /api/v1/market/tracking/episodes?view=active|archive`，静态路由置于`tracking/{code}`之前。
仓储在两次读取中取得每天最后发布的候选及空扫描日，先以分数做候选超集缩减，再由原领域筛选复核。
轮次ID由代码、策略配置、60F起点及首见日期生成，追加重复日不改变ID。观察/确认升级保留为一轮，首次状态仍冻结。
历史日K因子用`python -m jobs.repair_trend_factors --daily --start 2021-09-01 --end 2026-11-16`离线补缺，不推进日线同步水位线，HTTP不访问供应商。

`GET /api/v1/market/tracking?signal_date=YYYY-MM-DD`返回最近最多120个已有快照日期、所选冻结候选及前向统计；不存在日期返回404，不扫描历史全池补造名单。
`GET /api/v1/market/tracking/{code}?run_id=<uuid>&timeframe=1D|60F`校验原候选归属，延伸展示本地行情，原名单与新行情范围分开。
沿用全局JWT，入参先校验，仓储唯一执行SQL；不新增DDL或越层依赖。
日期/股票/周期快速切换会取消旧请求并忽略过期结果。日线采集完成后刷新页面即更新统计，不需要额外行情采集任务。

### 2026-11-16 日K母趋势与局部反转分层

`python -m jobs.annotate_trend_context`读取已有快照、本地原生日K并按股票/日期配对，生成新的派生快照，保留原version/config/as_of及全部信号字段，元数据独立记录parent_context_version/config/source_run_id；原快照不覆盖。结果先落`output/trend/parent_context_v1/snapshot.json`，`--publish-only`可幂等补发布。后续`scan_trend`会自动加入母趋势标注。这个分类层不改变原入场检查或既有量化回测数值，若用作新的买卖条件须另做研究验证。

### 2026-11-16 机会类型标注

### V7：安全边际与结构机会

低位反转、趋势回调（首次及后续再起）、未补缺口分别展示。不能把“不是新首阳”解释成“没有回调买点”。
趋势前置：日K M13在M21上、M21上行且收于M13上连续5日，已推进至少2ATR；回调0.5—3ATR、10日内且不跌穿M21减1ATR，触及13/21附近后转强，并有当天完整60F趋势恢复背景。第一次回调与后续回调分开计数；后续须先重新收盘创新高并与上一转强相隔至少3日，不重复冒充首次。
缺口前置：此前阴跌靠近10日低点；高开超过前高0.5ATR、较前收高开不超过2ATR、全天不补缺口且收阳，有量能支持；当天完整60F收于M8上、M8两根转升。止损按当日低点外0.25前ATR且至少1ATR缓冲，距离仍≤5%。这描述早期修复，不宣称M13/M21已多头排列。
普通阳线仍保留原风险、偏离与流动性门槛。首次回调优先辨识不等于绝对高胜率；价格已经上涨也不自动取消结构合格的回调。

### 4.1 v4.1两类机会与走势背景（历史兼容）

历史版本`dual-setups-v4.1`、`selection_mode=dual`。只筛两类做多机会；60F与原生日K分别运行同一套结构方法。
下面的N根都指所选周期，前置窗口均排除触发当根，ATR使用上一根已完成值。

**A：趋势中的回调介入**（`trend_pullback`）

- 先有升势：回调前四根以外、此前20根内曾满足EMA20>EMA60、慢线8根斜率为正、20根净推进≥2ATR。
- 再有受控回调：前20根高点至上一收盘回落1—6ATR，前收仍在EMA60−1ATR之上；60F还要求已完成日线方向向上。
  日K直接判断自身趋势，不额外强加周线条件。
- 止跌前兆：最近4根低点守住此前8根低点（容忍0.2ATR），并至少出现低点抬高、波动收敛、阴线实体减弱、缩量中的一项。
- 有效阳线收盘越过前根最高价，才开始观察；推进确认时须重上EMA20且快线转升，原趋势仍未破。

**B：横盘阴跌或砸坑后的反弹**（`base_rebound`）

- 横盘/阴跌修复：此前8根振幅≤3ATR且路径效率≤0.35，或此前12根净跌0.5—6ATR；
  最近4根守住此前8根低点，并有低点抬高、波动收敛、阴线实体减弱、底部盘整中的至少两项。
  有效阳线还须收盘突破前4根最高价。
- 砸坑收复走独立分支：最近4根之前先有12根平台（振幅≤6ATR、效率≤0.45），随后下破原平台低点1—4ATR；
  有效阳线须重新收回平台低点上方0.1ATR，且量比≥1。只有急跌、没有原平台，或仅在坑内反弹不能触发这一分支。
- **不要求日线多头**，允许均线仍偏弱。推进确认须站上正在转升的EMA5与本段冻结收复位；反弹候选不直接标为长期反转。

共同条件与计数：

1. 有效触发阳线实体≥0.35ATR、收盘超过前收/前高、位于本根振幅上部35%，相对前20根均量≥0.8。
2. 本轮第一根只观察；后续仅更高收盘、实体≥0.1ATR的阳线算推进。第2—4根推进当根才确认，不要求连续收阳。
   最多连续整理2根、整段最多12根；低点失守或显著回撤转弱结束本段。计数由`legs.py`共用，旧版本保持兼容。
3. 20个完整交易日日均成交额≥3000万元，本段路径效率≥0.45，向上偏离EMA20≤2.5ATR。
4. 参考止损取固定结构低点外0.2ATR与当前价下方2ATR的更低者，距离须≤8%；不缩紧止损凑信号。
5. 每类分别维护首阳与结构证据。相同确认级别优先A；B已确认时不会被A观察状态遮住。每股每周期最终展示一个主类型。

**先区别“初次反转”和“回调再起”，再解释本轮计数**：

- `swings.py`在局部启动段之上保留父级走势。除A/B结构种子外，也识别没有通过入选门槛的包阴强阳，
  作为背景：前8根至少两根阴线，本根实体≥上一根ATR的0.8倍、收盘包住这些阴线的实体上沿，
  开盘不高于其实体下沿+0.25ATR，收于本根振幅上部35%。这不是新增买入信号，也不要求未来出现连阳。
- 父级低点取记录起势当根与此前8根的最低值。短段回撤1ATR、整理超过2根、A/B类型切换均不清空背景；
  跌破父级低点0.2ATR，或收盘低于EMA60−0.5ATR且从父级峰值回撤≥3ATR，才结束背景。
  所有判断仅用当时已完成数据，不用未来走势回填过去阶段。
- 局部段产生时冻结阶段与父级信息；A本身就是趋势回调，归为`pullback_resume`；
  B若已有仍有效的父级走势，也归为再起，否则为`initial_reversal`。第2—4阳仍统计本轮，
  不把11月4日以来所有红K机械累加成一段，也不把局部重置当作整个趋势重新开始。
- 再起的第一根满足观察条件时显示“回调再起观察”，从“首阳”列表移出，可在“再起”直接查看，也保留在“观察”列表；
  确认后为“回调再起第N阳”。详情分开显示本轮转强与前次起势背景，CSV同时保留两个时间。

### 4.2 v3结构反转（历史兼容）

版本`60f-structure-v3`，`require_precursor=true`、`precursor_min_signs=2`。
识别日线大方向尚可时，60F回调结束或局部反转的候选；不声称预测最低点或保证反转。

**先看阳线出现之前的12根，再看触发阳线**。所有下面的窗口均排除触发当根：

- 必须守住低点：最近4根最低价≥此前8根最低价−0.2ATR（容忍很小的刺破）。持续加速创新低不能仅凭反弹进入观察。
- 以下四项至少满足两项：
  - 低点抬高：最近2根最低价，比再之前2根最低价高出0.1ATR以上。
  - 波动收敛：最近4根平均真实波幅≤此前4根的90%。
  - 抛压减弱：最近4根阴线实体总和≤此前4根的70%，且前一窗口阴线实体总和>0.1ATR；这是价格代理，不是资金流统计。
  - 底部盘整：此前8根振幅≤3ATR，路径效率≤0.35。
- 在上述前兆成立后，触发阳线还要收盘突破前4根最高价，满足既有实体/收盘位置/量比条件。
- 第一根**有效结构转强阳线**只观察；随后第2—4根推进阳线才可确认，继续检查日线、流动性、快线转升、追高和止损距离。

因此“首阳”是本规则首次确认结构转强的阳线，不一定是最低点后的第一根阳线。
首阳时将结构证据、当时阻力位一起冻结到本段，之后不会用未来K线补造理由；看板和CSV均展示证据。
结构前兆也可能失败，两项价格代理可能相关，不能把命中数当胜率。V形直线反弹会被更谨慎地过滤，收益与误报率仍待样本外回测。

### 4.3 v2启动段（历史兼容）

`selection_mode=early`，版本`60f-startup-v2`。目标是尽早发现一段上涨，而不是等整段趋势走完才追认。
所有信号均在对应60F收盘后成立；首阳是**当时可见的尝试启动**，不保证后面一定有第二阳。

1. 大方向沿用已完成日线过滤与20日日均成交额≥3000万元。
2. 先有回调或盘整：前20根高点相对上一收盘回落≥1ATR，且前收低于EMA20或此前3根至少2次收盘下降；
   或前8根振幅≤3ATR、8根路径效率≤0.35并突破前4根高点。窗口都排除当前根。
3. 首阳实体≥上一根ATR的0.35倍、收盘高于上一根收盘/最高价，收盘位置位于本根振幅上部35%，量比≥0.8。
4. **首阳只观察**，保留日期/起点价格与结构低点。观察允许价格尚未收复EMA20，不强迫提前确认。
5. 后续阳线仅当收阳、收盘超过上一根已计数阳线的收盘价、实体≥上一根ATR的0.1倍时才算一次推进。
   小阴线、十字星和未创新收盘的阳线不递增、不重置；最多允许连续2根整理，超出即取消早期资格。
6. 仅在本段**第2、3、4根推进阳线当根**产生候选，且启动至今不超过12根60F；第5根以后不列为早期候选。
7. 候选须收盘重上EMA20且该快线转升，本段净推进/价格路径≥0.45；不强等EMA20/60金叉、ADX20或20根ER。
8. 仍检查偏离快线≤2.5ATR、正的参考止损及风险距离≤8%。止损使用本段固定结构低点外与2ATR中更低者，
   不为了让信号通过而缩紧。跌破本段低点，或从段内高点回撤≥1ATR且转弱，结束本段。

新旧规则可用`selection_mode=early/mature`明确区分；v1快照缺少该字段时，查询按mature保留原解释。
v2质量排序采用条件通过程度、本段效率、2→3→4的时效分与风险距离，ADX/20根ER仍可查但不是早期门槛。

### 4.4 v1成熟趋势规则（历史兼容）

1. 日线由同源60F中每天4根完整K线合成，只在15:00后可用；EMA20 > EMA60，EMA60近3日上行。
2. 60F收盘 > EMA20 > EMA60，EMA60相对8根之前上行。
3. 20根效率比 `ER = |C[t]-C[t-20]| / sum(|ΔC|)` ≥0.30；14期Wilder平滑ADX≥20。
4. 20个完整交易日日均成交额≥3000万元。
5. 收盘不低于EMA20，且距其不超过2.5ATR，避免过度追高。
6. 突破：收盘高于**不含当前根**的前40根最高价，成交量≥前20根平均量的1.2倍；
   或回踩：前4根有低点接近EMA20（允许0.5ATR）且对应收盘守住EMA60，当前阳线重上EMA20并高于前收。
7. 参考止损为 `min(近8根最低价 - 0.2ATR, 当前收盘 - 2ATR)`；必须为正且距离≤8%。
8. 当前简称含ST/退市标记、缺失真实因子、末根落后截止点的股票不能成为候选。

参数统一由 `TrendConfig` 管理，可用JSON文件传入离线任务；每次参数与策略版本一并保存。
最少需要约63个完整交易日热身；数据不足不会补出指标。分数只排序通过程度、ER、ADX与风险距离。
价格按 `raw_price × factor_on_bar_date / factor_on_cutoff_date` 处理；成交量仍为股、成交额仍为元，
展示的是截至该日的价格复权序列，不使用未来复权因子。均量比不对股本变化做额外调整。
该价格口径覆盖分红、送转等造成的除权除息价差；OHLC、ATR、策略EMA及图表MA均在同一复权价格尺度上计算。
因子缺失、非有限正数或复权价格溢出/下溢时，展示原价并禁止信号；不猜测或填充因子。
图表的M8/M13/M21按所选周期最近8/13/21根已收盘K线的收盘价做简单平均，不是EMA；
日K按交易日、60F按实际60F根数计算，不补周末/停牌K线。计算在截取最近1000根之前完成，左边界不会重新预热。
价格复权不能直接替代现金分红到账与送配股的逐笔台账；回测现有因子份额近似保持原实现与限制，见[量化策略与回测](../agents/quant_backtesting.md)。
口径参考[Tushare复权行情说明](https://tushare.pro/document/2?doc_id=146)及[分红送股字段](https://tushare.pro/document/2?doc_id=103)。
