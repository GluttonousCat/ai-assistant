# A股上市公司财务 Agent 系统

> **Alpha Finance Radar** · 个人研发阶段（独立设计开发中）

面向 A 股上市公司的一站式智能投研助手：自然语言随意提问，Agent 自主调用数据工具，
完成财务查询、研报解读、产业链映射、预期差分析与量化形态判定，
并以多轮对话的方式支持追问、质疑与核验。

## 一、数据来源

| 来源 | 内容 | 处理方式 |
|------|------|---------|
| **Tushare** | 日线行情、财务三表、108 项财务指标、估值（PE/PB/市值）、主营构成 | 定时同步入 PostgreSQL 数仓（stock / fin 双 schema，千万级行情数据） |
| **巨潮资讯** | 上市公司年报原文 | 报告原文获取与结构化（配合财务指标做交叉核验） |
| **个人知识星球** | 券商研报（每日抓取） | 反检测爬虫 → LLM 结构化入库（机构/标的/评级/盈利预测/tags，输出一律中文）；图片型扫描件走视觉 OCR |

## 二、技术架构

**前端 React + 后端 FastAPI + PostgreSQL + LLM（deepseek / qwen 双模型路由）+ MCP 工具层**

```
React (Vite)                     FastAPI                        PostgreSQL
├─ Agent 对话页 (SSE 流式)        ├─ JWT 鉴权 (三级角色)          ├─ stock: 行情/估值/日历
├─ 研报中心 (AI 分析流式弹窗) ←─→ ├─ Agent 对话循环 ──┐           ├─ fin:   财务三表/指标/研报
├─ 产业链页 (环节→标的映射)  SSE ├─ MCP 工具注册表   │           └─ 视图层: 宽表/清洗视图
├─ 区间看板 (lightweight-charts) ├─ 研报流水线 API   │
└─ 用户/角色管理                 └─ 调度器 ──────────┘
                                  (Tushare 同步 / 研报爬取 定时任务)
                        Agent 循环:
                        LLM function-calling × 17 只读工具 (≤8 轮)
                        ├─ 同轮多工具并行执行
                        ├─ 简单查询快车道 (LLM 生成 SQL, 秒级; 规则引擎兜底)
                        ├─ 会话历史 (多轮追问/省略主语解析)
                        └─ 沙盒: 只读/超时/轮数上限/防重复
```

- **LLM 双模型路由**：deepseek（推理/工具调用/解读）+ qwen（视觉，扫描件 OCR），
  按用途统一工厂分发；思考开关与 token 预算由客户端层集中注入
- **MCP 工具层**：18 个投研原子能力（财务查询/主营构成/估值分位/研报检索与问答/
  盈利预测/产业链/预期差/技术指标/量化扫描/财务排雷/预测兑现校验…），
  同一份 ToolSpec 双形态导出——内部 Agent function-calling 与外部 MCP stdio 协议复用，
  外部服务默认只读模式；对话入口见「四、Agent 设计」的三级分发

## 三、核心能力

- **随意问**：BI 查询及延伸问题、研报观点、产业链环节、预期差四象限、量化形态、财务排雷，
  一套对话入口全覆盖；复合问题自动多工具组合
- **多轮追问**：「中际旭创年报净利润多少」→「环比竟然下降了，数据对吗？」——
  自动继承上下文标的，重新取数拆单季核验，识破累计口径假象
- **口径内行**：财报累计口径 vs 单季环比、预测分歧度 CV、估值历史分位等专业口径
  内置于提示词，质疑类问题强制重新查证而非凭记忆辩解
- **研报流水线**：爬取→下载→LLM 元数据提取→深度结构化→去重，逐篇入库即前端可用；
  扫描件后台视觉 OCR 后自动接续
- **量化子系统**：震荡区间 8 状态机、趋势扫描、蓄势盾形态、技术指标（ADX/POC/Wyckoff），
  全部可经对话调用

## 四、Agent 设计

按 **OpenAI function-calling 协议**实现：LLM 自主决策 + 工具循环
（替代传统的「意图分类 + 固定管道」范式），相关 MCP 工具按职能分组为 **6 个域子 Agent** 调用。

### 4.1 三级分发（闸门判定零 LLM 规则化，逐级放行）

```
用户问题
  ├─ ① 快车道: 高置信简单查询 → LLM 生成 SQL (nl2sql 用途关思考, 2~7s;
  │            规则引擎兜底) → 校验执行 → 图表+规则简报
  ├─ ② 域子Agent: 单域命中 → 域内 2~4 个工具 + 域专家提示词 + escalate 升级伪工具
  └─ ③ 全工具循环: 复合/模糊/定义类/升级续跑 → 17 个只读工具自由组合 (兜底永在)
```

**性能分级（实测）**：简单查询 2~7s（快车道，LLM 生成 SQL + 图表，时间口径由
prompt 内置规则保证，如"最近三年"= 最近 3 个年报）；域子 Agent 10~20s；
跨域复合/升级 30~60s——耗时主体是 LLM 思考推理，路由本身毫秒级。

**路由判定规则（宁漏勿误：路由是缩小菜单的优化，不是能力闸门）**：
核心词恰好命中 1 个域 → 该域子 Agent；命中 ≥2 个域（复合问题）或 0 个（模糊口语）
或定义/解释类问法（"什么是…"）→ 全工具循环。漏路由只是少优化，误路由才是事故，
因此任何复合嫌疑都放行全循环。

### 4.2 六个域子 Agent（缩小菜单 = 降低弱模型误选率）

| 子 Agent | 域内工具 | 职责 |
|---|---|---|
| 财务数据 | query_financials / query_main_business / valuation_percentile | 指标查询·主营构成·估值分位 |
| 研报观点 | search_reports / read_report / get_forecasts / extract_document | 研报检索·单篇问答·盈利预测 |
| 产业链预期差 | list_chains / analyze_chain / analyze_alpha | 环节映射·四象限综合 |
| 量化形态 | compute_indicators / run_quant_scan | 状态机形态·技术指标·扫描 |
| 风控校验 | detect_financial_risk / verify_forecasts | 财务排雷·预测兑现校验 |
| 实体日历 | resolve_stock / get_schema / trading_calendar | 实体解析·数据字典·交易日 |

### 4.3 循环与升级机制

- **决策循环**：每轮一次 LLM 推理——"还缺数据"则发起工具调用（同轮多个并行执行，
  结果按原始顺序以协议规定的 JSON tool 消息回填，`tool_call_id` 配对；
  并行只省墙钟时间，对下一轮模型完全等价于串行），"信息够了"直接输出最终回答。
  **终止权在模型手里**（实测多数问题 1~2 轮收笔），≤8 轮上限、
  同参 ≤3 次、同名 ≤4 次的护栏只是防失控保险丝
- **escalate 升级链路**：域子 Agent 发现需要域外能力时主动申请升级，
  同一上下文无缝切换全工具清单续跑（不重查已有数据）；
  升级动作作为 SSE 事件下发，前端步骤卡与评测报告均可观测
- **执行层白名单**：只执行当前清单内的工具，模型幻觉调用清单外工具会被拦截，
  返回教学式错误（"本子Agent未开放此工具，需要请调 escalate"）——
  把模型的越权冲动转化为设计内升级（实测捕获并修复过模型越权调用）

### 4.4 安全与记忆

- **沙盒**：对话只见 17 个只读工具；每工具超时；同参 ≤3 次/同名 ≤4 次防刷；
  SQL 工具内嵌白名单校验（只读 + schema 限定 + 强制 LIMIT）
- **多轮上下文**：会话历史注入（用户问句 + 回答 + 工具调用摘要），
  「环比竟然下降了，数据对吗？」这类零线索追问可正确继承标的与指标

## 五、工程质量

- **Agent 评测体系**：24 轮真实 LLM+数据库端到端用例（15 类：单域查询/复合意图/
  多轮追问/纯常识/未来期间/库外标的/泄漏防回归），基线通过率 100%，
  改提示词/工具描述后回归验证；研发期实测抓出并修复：模型幻觉越权调用、
  子 Agent 按环节逐个刷工具、快车道劫持常识问题等真实缺陷
- **测试**：pytest 覆盖 Agent 循环、MCP 注册表契约、会话历史、快车道判定、
  并行执行、域路由与白名单
- **安全**：SQL 白名单校验（只读+schema 限定+强制 LIMIT）、工具只读沙盒、
  JWT+DB 实时角色校验、服务输出重定向与同步 IO 线程化
